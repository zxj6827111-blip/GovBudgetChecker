## 一、F5-REF：删除自证映射，改为冻结例外清单 + 独立校验

### 问题

上一版在运行期从“待检查引用本身”的同位置差异/共现票推导 `new→old` 映射。隔离变异把
`CMM-013-8` 改成 `CMM-013-999999`、`CMM-011-16` 改成 `CMM-011-999999` 后，工具仍生成
“已验证映射”并 `ok=true`，掩盖了与 `result.issues`、`related_findings` 的断裂。

### 修复

1. **删除运行期推导**：不再有 vote/pre-group 顺序映射，不再从引用差异反推映射。
2. **冻结精确例外清单**：`scripts/fp_batch1_reference_exceptions.json`
   - 45 条引用重编号精确条目：`(doc, old_id, new_id, path, old_value, new_value)`；
   - 另 1 条计数例外（见下节）；
   - 清单由正常冻结采集一次性导出，运行时只读、不推导，供复核方逐条审核。
3. **每条引用变化必须同时通过**：
   - 精确命中冻结条目（值、路径、新旧条目 ID、文档全部一致；跨文档/跨规则不命中）；
   - 新引用 ID 的编号不超过基线 run 同前缀最大编号（只允许重编号变小，999999 直接拒收）；
   - **跨表示一致性**：`review_report` 中同一实体的引用必须与 `result.issues` 中的原引用一致；
   - **成员归属**：`member_issue_ids`/`merged_issue_ids` 必须与 `related_findings` 的成员引用集合一致；
   - **双向唯一**：例外清单与运行时应用均检查“新→旧”和“旧→新”唯一，多新映射同一旧即拒收。
4. 未命中/未验证的引用变化一律进入 `raw_fingerprint_drift`，`ok=false`。

### 正常采集（round2/gold/run1，冻结）

- `ok=true`、exit 0；
- 45 条引用例外全部精确应用（`reference_exceptions_unused=0`）；
- `reference_exception_conflicts=0`、`raw_fingerprint_drift=0`、`raw_missing=0`；
- 指标不变：F 130、TP 101、**28/130=21.5%**、漏报 86/146、P 73、O 90。

## 二、F5-COUNT：计数例外精确核验

### 修复

`partial_findings_count` 不再是“路径属于目标规则就放行”，而是冻结条目
`(doc, old_id, new_id, path, rule_id, old_count, new_count, removed_count)` 精确匹配，并额外核验：

- 旧值、新值精确一致（本批唯一合法变化：GS-2025-01 / V33-TREND-COMPLETION-RATE / 1→字段省略，0）；
- `rule_id` 一致；
- `removed_count` = 该文档该规则的目标移除条数（本批为 1）；
- `old_count - new_count == removed_count`。

999、方向错误（1→2）、移除数量不符（removed_count=2）均拒收。O 层 `detail` 的宽泛
“含 fail→pass 即通过”例外已删除；当前匹配 O 条目无 detail 变化。
