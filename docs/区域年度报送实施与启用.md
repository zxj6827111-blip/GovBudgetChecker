# 区域年度报送：实施与启用说明

## 已实现的入口与口径

- `/materials` 为区域报送台账；`/supervision` 为共用统计服务的主管视图。`?legacy=1` 保留历史材料查询。
- 任务按报送年度和地区唯一。2026 任务默认引用 2026 预算、2025 决算，不改变材料财政年度。
- 市本级只纳入最近行政区划为该市的部门、单位；区县单独统计。地区来自授权组织目录，不依赖已有上传。
- 默认按本区域组织目录中的全部部门及下属单位统计应交，每个主体每个文种各一份，不依赖是否上传、是否建立槽位或是否发布草稿。单一文种应交＝部门数＋单位数；全年预算＋决算合计为两类材料之和。未交＝应交－已交，完整率＝已交÷应交；应交为零时不显示100%。
- 已有特殊范围的已发布名册继续使用发布快照；管理员仍可配置不适用或排除等例外并发布。读取目录应交范围不会自动更改、确认或发布草稿，不修改已有材料及归属。全部未交项都缺少截止时间时，逾期保持未知。
- 名册发布在一个数据库事务中保存预算和决算快照，并切换生效版本。草稿修订不会改变现行分母；财政年度配置修订也要再次发布才生效。
- 文件事实决定已交，分析中、分析失败、复核完成均不改变报送判断。必须是归属于该槽位的当前有效版本；归属/口径歧义不作为匹配材料。
- 人工确认问题、待复核线索、补核待办分别统计。旧文件、旧分析代际的结论不进入当前统计。确认问题可进入具体文件版本的人工复核结果；版本变化会提示查看历史。
- 关键词、部门、主体、状态只筛选明细；顶部仍显示任务、地区、材料范围下的区域总计。URL 与 CSV 保留筛选；导出不受当前分页限制。
- 清单外上传不会使生效名单失效。组织归属按发布快照保存，目录变化提示修订，不静默更改历史责任范围。

## 权限与归属核查

管理员创建、配置、发布、归档及确认归属修复。工作人员按现有组织授权查询、查看已发布名单及依据；主管只读。父级容器可见不扩大下级材料权限，CSV 同样过滤。

工作人员可以查看授权任务内的归属核查；管理员还可勾选全部历史分类：历史 ID、缺失祖先、身份/口径待人工核查、无完整材料链路的旧分析任务。每条显示处置状态。其他年度保留只读分类，不能直接套用当前任务修复。

修复必须先预览，提供同一主体依据并确认。运行中的分析/复核、目标身份冲突、预览后记录变化均拒绝。原始文件、业务 ID、版本、历史复核保留；恢复凭证保存在组织数据目录的 `identity-repairs/<receipt-id>/receipt.json`。

历史 ID 修复沿用现有跨数据库/文件修复服务。真实执行前应暂停上传和组织目录维护，保存数据库、组织目录、任务关联和状态文件备份。不得以名称相同作为同一主体的唯一依据；实质主体变化继续人工核查。数据库中完全没有记录的旧文件任务仍需通过历史“归属待核查”入口核对，不能因为本清单未列出就认为已完成。

恢复命令（先预览，后执行；后续业务变化会阻止覆盖）：

```sh
.venv/bin/python scripts/recover_reporting_identity.py --receipt /实际组织目录/identity-repairs/凭证ID/receipt.json
.venv/bin/python scripts/recover_reporting_identity.py --receipt /实际组织目录/identity-repairs/凭证ID/receipt.json --apply --actor 实际操作人
```

## Mac 启用步骤

新视图通过 `GOVBUDGET_REPORTING_TASKS_ENABLED` 控制，默认关闭；这样代码更新不会在数据库迁移和真实验收之前直接切换业务视图。

1. 在 Mac 项目目录、使用实际服务环境变量，执行现有 `scripts/backup_all.py create` 并 `verify`。备份应包含 PostgreSQL、原文件与任务状态、审计日志，以及组织/关联/用户等应用状态；检查 manifest 的实际覆盖路径。备份失败不得启用。
2. 使用同一虚拟环境与 `DATABASE_URL`、`PG_SCHEMA` 执行 `scripts/run_db_migrations.py`。新增迁移为 `2026-10-23_0040_reporting_tasks`，只新增结构，不生成真实任务和名册。迁移脚本会执行第二遍校验幂等。不要把测试库连接串用于这里。
3. 在实际服务环境设置 `GOVBUDGET_REPORTING_TASKS_ENABLED=true`，按现有启动方式重启后端与前端。开发模式可用项目既有 `npm run dev`；生产模式沿用现有部署流程重新构建和重启。不要启动重复服务。
4. 管理员打开 `/materials`，分别创建上海市本级、普陀区2026任务。默认立即按各地区组织目录计算应交及未交，并保留未上传部门和单位的明细入口。仅有特殊不适用、排除或冻结责任范围需求时，再配置并发布特殊名册。截止时间不明确时保持未知。
5. 在 Mac 实际浏览器核对同一范围的台账、驾驶舱、明细、原文、导出；用受限账号核对权限。页面数字必须可追到名单、有效文件和对应复核结果。
6. 将真实未归属材料分类，优先处理 2026 预算和 2025 决算。其他历史材料分批核查；不要求强行把既有 79 份全部归零。目录模式下未交名单反映当前组织目录，应先核对目录的漏项、重复或历史机构，再用于正式催报。

这些脚本需要从已加载实际服务环境的终端运行；`run_db_migrations.py` 本身不会自动读取 `.env`。需要加载时可通过 Python 的 `load_dotenv` 在同一进程调用脚本，例如：

```sh
.venv/bin/python -c 'from dotenv import load_dotenv; import runpy; load_dotenv(".env"); runpy.run_path("scripts/run_db_migrations.py", run_name="__main__")'
```

## 回退

先将 `GOVBUDGET_REPORTING_TASKS_ENABLED=false` 并重启后端，前端自动回到历史查询。保留新增表和名册版本，不删除已产生任务数据。程序文件可按本次差异备份恢复；任何归属修复必须按其单独凭证恢复，不能用整体源码回退冒充数据恢复。

## 验证边界

本次开发验证使用 Windows 上隔离 PostgreSQL 随机 schema 和临时组织、用户、文件。接口校验装载真实报送路由及授权逻辑，绕开项目现有依赖 `fcntl` 的无关 macOS 纠错模块；不能替代 Mac 全进程验收。正式启用仍需真实环境备份、迁移、服务重启与管理员名单确认。
