## 三、冻结的实现契约

### C1：结果与完成状态独立

- 三个入口保持现有对外返回类型，规则层继续使用原始 Issue；异常载荷不能提前转成 dict。
- `partial_issues` 采用可选、向后兼容参数，避免可变默认列表；仅装入完成验证的独立结果。
- 独立子检查全部尝试执行，汇总所有缺失原因后再报告未完成，不能遇到第一处缺失就中止其他独立检查。
- 一条规则只有一个 outcome；保留旧摘要字段和含义。finding 数、未完成子检查及原因使用增量字段表达，不通过重复 outcome 虚增规则数。
- 当一个规则存在多种未完成原因时，所有原因保留；规则聚合状态采用明确且有测试的优先级，例如 execution_error > parse_error > insufficient_data。部分子检查 not_applicable 不能覆盖其他子检查的 fail 或未完成。
- 找到问题和检查未完成可以同时存在；但任务仍为 review_required/incomplete。未完成状态不能把已经确认的问题隐藏掉，也不能算成全部已核验。
- 规则层 partial Issue 和正常 Issue 共用排序、编号及序列化路径；EngineRuleRunner 共用转换、定位、版本留痕和转换失败处理。
- 原有缺数据原因与新增转换失败原因必须同时留下；有效部分保留，转换失败部分不得伪装正式问题。
- 更新 rule_outcome.py 中“只有 fail 才能有 finding”等已不适用的注释/契约。不能只改实现而保留相反文档。

### C2：严格取数及比较

- 保持 `_row_value` 的旧签名和返回类型；新增严格接口并显式迁移调用方，不为兼容性让旧不可靠兜底继续参与已迁移规则的确定性比较。
- 严格值保留原文、Decimal、原始单位、原始显示精度、归一化金额、来源位置、列定位依据和缺失原因。未知/空白与明确零不同；不能由 float 重建小数位。
- 多层表头、同名列、预算/决算列组必须消歧；full_extent 只提供候选范围，不证明续表身份和列序一致。
- 金额比较有输入前提：同年度、指标、预算/决算口径及资金范围可对应，单位和精度可证明。歧义进入未完成。
- 求和、两端同口径相等、百分比复算使用各自策略；保留 BUD-111 现有百分比口径。不全局重写 `_is_close`。
- 不改变既有 severity 分级契约。info/舍入提示和真实缺陷的评价口径分开，不能把错误全部降级刷绿。

## 六、禁止的“修绿”方式

- 删除/跳过失败测试，放宽断言、质量门阈值，缩小 Golden 真值组或修改 sample.pdf 迎合输出。
- 将正式错误全部降为 info/manual_review，或所有规则都 Deferred 来获得零误报。
- 按样张文件名、单位名称、特定 SHA、固定页码或某个金额写特殊放行逻辑。
- 测试只 mock 新取数器返回正确值，却从不运行实际规则和真实解析输入。
- 正式测试导入 outputs 下的临时脚本，或依赖个人磁盘路径、项目 .env 密钥。
- 改动后复用旧缓存、旧 PDF 或不同配置的输出作为“修后通过”证据。
- 只报告 findings 总数、测试总数、Golden PASS，而不提交失败/跳过/未完成项。

正常样例触发误报时，先检查字段、口径、表身份和精度。不能通过重新放大金额容差掩盖根因。

## 七、证据包与交付格式

每批在独立的 `outputs/remediation_v4/<run-id>/` 目录保存证据。输出目录通常不入仓，必须在交付中给出绝对路径；需要提交的轻量测试夹具索引与阶段报告单独入 tests/fixtures 或 docs/，避免 Git clone 后证据索引失去解释。


不保存密钥或完整环境变量转储。逐项差异至少记录 PDF SHA、规则、业务对象、旧/新值或状态、双方位置、原因、裁决状态。实施代理的“真问题/误报”判断必须附原文依据；未经独立核实的不标成最终真值。

2. 变更行为和修改文件；是否有范围外改动。
3. 测试命令、退出码、通过/失败/跳过数量及证据绝对路径。
4. 已知缺陷是否消除，哪些只有合成证明，哪些有真实 PDF 证明。
5. 未决问题及建议，不自行猜测批准。
6. baseline_commit、当前 HEAD、本轮工作树差异与拟提交依赖分组；确认本轮未 push、未操作生产数据，不把既有已推送提交计入本轮成果。
