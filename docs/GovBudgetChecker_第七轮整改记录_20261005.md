## 实际下载验证及额外修复

五组下载来自实际主链分析、校正接口、人工决定及下载处理函数，输入为明确标识的合成预算 PDF；在隔离文件系统中运行，认证存储边界使用测试替代，无真实数据库。因此，这五组是生产函数回归证据，不是独立盲测或完整部署证明。

| 组别 | 状态/版本 | 四格式门禁 |
|---|---|---|
| 01_current | 原始100，原问题confirmed | computed，一致 |
| 02_current | 100→90校正后当前版 | computed，一致 |
| 03_historical | 校正后下载原版本 | computed，一致 |
| 04_historical | 新版决定no_issue之后再次下载原版本 | computed，一致 |
| 05_current | 110及no_issue的新版本 | computed，一致 |

历史03/04的 JSON、CSV、DOCX、PDF 字节一致；新决定未覆盖旧版决定，源 PDF 未修改。实际原样产物保留在 `export_probe/`。

复核中额外发现并修复：

1. **Word 下载时刻不稳定。** ZIP 默认时间戳及正文“检查时间”使用生成时刻。ZIP 元数据改为固定容器时间，正文改为该报告的分析版本；测试模拟相隔一天的下载，确保同一历史内容字节一致。
2. **中文 PDF 丢失数学减号。** 真实决算 CMM-007 建议中的 U+2212 被原中文 CID 写字路径丢弃。附录使用带字形回退的 TextWriter，完整保留“本期−基期”；新渲染器版本进入派生文件缓存键，既有派生文件保持不变。新增实际下载及四格式门禁测试。
3. **验证器一致计数不严谨。** DOCX/PDF 语义核对失败时，以前仍可能把该文档计入一致数量。现在只有该文档所有结构和可见语义校验都通过才能计入一致。隔离服务脚本同时要求 `status=computed` 和完全一致，不能用不可计算结果中的计数冒充通过。
4. **Word 长记录排版。** 多列回执、人工决定及复核原因表改为两列记录，正文栏加宽，保持完整 ID 与语义字段。实际 DOCX 经 LibreOffice 渲染检查；CJK 字体映射仅配置在本轮 QA 目录，未修改系统字体或生产运行配置。

原门禁错区域、错哈希、缺认证、缺真值、篡改回执/容差/引文、互换问题内容反例继续拒绝。没有把严格校验退化成全局关键词匹配。
