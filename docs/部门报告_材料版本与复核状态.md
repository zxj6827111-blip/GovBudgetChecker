# 部门报告：材料、文件版本与人工复核

本次优化保持材料台账、处理队列及任务历史各自的用途，部门报告以已收到的材料槽位为主行。

## 使用口径

- 材料身份沿用组织 ID、主体层级、财政年度、文种和材料范围，不按同名组织合并。
- PDF 哈希相同复用文件版本；不同内容形成新版本。文件版本号在材料内部排序，不展示全局数据库 ID 为版本序号。
- 分析任务与文件版本分别计数；同一任务的历次分析代际在历史展开中按需读取。
- 复核状态必须同时匹配槽位、文件版本、任务及分析代际。确认问题数来自完成复核时冻结的快照。
- “已复核”不等于无问题、整改完成或正式验收通过。问题数缺失显示未记录，不补为零。
- 新版优先显示；尚未分析或分析失败也保留材料。旧复核结论在历史中保留，不继承到新版。
- 未归属记录与旧组织 ID 的材料仍可从“待确认归属”查到，不按名称推测归属。未收到的应收材料继续由台账管理。

## 接口与实现

- `GET /api/materials/reports`：支持 `org`、`org_scope=exact|descendants`、`year`、`kind`、`q`、`review`、`page` 和 `page_size`；返回当前页材料摘要、组织材料数、未归属记录数及轮询状态。
- `GET /api/materials/reports/{slot_id}/history`：按需返回版本、可访问的任务、复核历史。分析代际复用既有任务接口。
- `GET /api/files/{job_id}/source?checksum=...`：沿用任务鉴权，并核对请求所指的 PDF 哈希。错误响应由代理保留。找不到原件时列表不提供下载链接。
- 槽位可见范围沿用台账授权；运行、计数与原件入口另外使用实际任务授权，不能用旧数据库归属扩大权限。
- 列表固定批量 SQL 查询，不取完整发现或证据；只对当前页及用户展开的历史检查原件入口，不扫描整个上传目录。
- 完成/重开复核及复核台重新分析触发列表失效通知；返回、重新获得焦点及手动刷新重新读取。刷新失败保留上次结果并显示错误。
- `/api/jobs` 继续按任务计数。页面保留“任务历史（兼容入口）”，不将旧任务接口伪装成材料汇总。

## 上传与迁移

上传后即登记身份明确的 PDF；解析复用同一份组织身份和文件哈希，不重复建版本。登记失败保留原件及任务，在待确认区展示。

新增迁移 `2026-10-23_0039_material_document_identity`：

- 文档唯一性增加组织 ID，防止同名单位共用文件版本；旧文档只在槽位主体唯一时回填身份。
- 授权及列表字段使用生成列，避免为列表逐行展开大型 metadata。
- 迁移不改变文件版本 ID、文件哈希、原件、分析结果或复核会话。CSV 导入脚本同步使用新的唯一性目标。

上线前先验证迁移及字段再部署新接口。界面回退可使用任务历史入口；若已有同名不同组织的新文档，不应直接恢复旧唯一索引或旧版写入器。

## 历史归属修复

只读盘点：

```sh
.venv/bin/python scripts/preview_material_identity.py --output artifacts/identity-preview.json
```

候选不是已确认映射。只有用户确认具体旧 ID、新 ID 与材料槽位后，才准备 `confirmed=true` 的审批 JSON，并执行：

```sh
.venv/bin/python scripts/repair_material_identity.py --approval APPROVAL.json --receipt-dir RECEIPT_DIRECTORY
```

修复会检查主体层级、目标冲突、正在运行的任务及复核；按统一锁顺序锁定相关记录。保留槽位、版本、任务、复核会话 ID 与冻结结论，更新现行组织归属和任务关联。文件修改前字节及数据库前值写入恢复目录；遇并发变化拒绝覆盖。

回滚仅在没有后续业务修改时允许：

```sh
.venv/bin/python scripts/repair_material_identity.py --rollback RECEIPT_DIRECTORY/receipt.json
```

数据库与文件不是分布式事务。进程异常时保留 `pending` 凭证和 before 文件，先核对实际提交状态再恢复，不擅自覆盖后续业务修改。
