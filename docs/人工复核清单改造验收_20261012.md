# 人工复核清单改造验收

日期：2026-10-12。范围：用户确认的方案 1「清单后进入详情」。

## 已实现的用户流程

1. 点击侧栏「人工复核」，进入 `/review` 材料清单，不自动选择任务。
2. 默认显示待办，支持复核状态、财政年度、部门或单位、文种、关键词筛选和分页。
3. 点击「查看材料」进入只读预览；用户点击「开始复核」后才可提交问题判定和检查补核。
4. 「完成复核」继续由服务端校验。无问题、分析结束、看过材料均不能自动表示复核完成。
5. 返回时保留来源列表和筛选条件。从处理队列进入时，返回处理队列并恢复其筛选、排序和页码。
6. 从复核清单进入时，「查看下一份」遵循当前筛选，末尾不循环或跳到其他年度。
7. 小窗口自动收起导航，仍可手动展开。列表优先显示材料、复核状态、待处理事项与操作。

「处理队列」负责机器分析的运行记录、阶段进度、重试和异常；「人工复核」负责当前材料版本的人工处理。

## 状态和接口口径

新增只读 `GET /api/reviews/worklist`，Next 同路径代理。

| 状态 | 语义 | 计入待办角标 |
| --- | --- | --- |
| pending | 当前分析可读，尚无当前版本和代际的有效复核 | 是 |
| in_progress | 当前版本和分析代际上有进行中的会话 | 是 |
| invalidated | 有历史复核，当前版本或分析代际需要重新复核 | 是 |
| completed | 当前版本和分析代际已有持久化完成记录 | 否 |
| waiting_analysis | 当前分析尚未产出可读、落库的结果 | 否 |
| history_only | 历史任务没有准确材料关联，仅提供只读查看 | 否 |

- 按 `slot_id` 的当前文件版本归并，运行的选择复用材料详情的排序函数，不按名称猜归属。
- 复核记录同时核对槽位、文件版本、分析任务和分析代际。
- 待判问题与检查待补核分别计数，复用现有服务端判据；未知检查覆盖显示未知。
- 查询按材料组织范围过滤，再核对当前任务读取权限。数据库异常返回 503，前端不显示虚假的零待办。
- 清单批量获取运行、会话和补核决定，不逐行请求详情 API。
- 返回地址只允许受支持的站内列表路径，拒绝外部地址与递归详情参数。
