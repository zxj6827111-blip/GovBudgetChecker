方法：逐份检查该材料 upload 目录里的 `status.json`（系统自己的历史作业产物），
读 `result.rule_findings` / `result.meta`。**注意旧 schema**：这些产物用的是
`result.rule_findings`，不是现在的 `issues` 分桶，按新 schema 读会误判成 0 条。

| 结论 | 份数 | 说明 |
|---|---|---|
| 有**旧版**生产输出（可作预标注候选，见下） | **27** | `status.json` 里的 `result.rule_findings` |
| 从未被系统分析过（无候选清单） | **3** | 长风街道2025决算、规划和自然资源局2024（`f2546b577801`）、财政局2024决算 |

**⚠️ 订正（读 WP4-I 方案正文后，2026-09-28）**：本节初稿写「有历史输出即失去盲标
资格、L2 只能外采」——**与方案的明确规定冲突，是错的**。方案 §3.2.2 原文：

> **预标注限历史任务**：来自 `uploads/` 的材料，其**旧版系统输出**可作候选清单发给
> 标注人做「确认/否决/补充」，但**当前代码输出一律不可见**。

即：**旧版输出被明确允许**当候选清单（它是上一代引擎的结论，用来做"确认/否决/补充"
反而有助于抓漏检）；被禁的是**当前代码的输出**。据此重排：

| 组 | 材料 | 当前引擎输出可见性 | 结论 |
|---|---|---|---|
| A | 已登记的 7 份（含 4 份决算） | **已公开**——我跑了 `run_benchmark`，逐条 finding 与规则级证据写在 `docs/B1_BENCH_DELTA_20260928.md`、`docs/B1_YICHUAN_13_EVIDENCE_20260928.md` 与 PR 评论里 | 这 7 份**L2 不可盲**（当前输出已可见）；只作锚定观察面 |
| B | 其余 23 份本机候选 | **不存在**——我没有在它们上跑过当前引擎，文档里也没有它们的逐条输出 | **保留 L2 盲标资格**；按 §3.2.2 用旧版输出做候选清单即可 |

**对 S3 的直接后果**：L2 深标的 20 份**不必全部外采**——B 组 23 份本机材料可承担
相当一部分，前提是**登记后不要先跑 `run_benchmark`**（一跑当前输出就落盘，该材料
即落入 A 组的境地）。这也是 `docs/B1_CORPUS_CHECKLIST_20260928.md` §三 把
「登记后先别跑 benchmark」写成显式警告的原因。

**一条运行纪律**：今后凡「打算用于 L2 盲标」的材料，登记后只许跑 L1 阶段不产出
findings 的检查；`run_benchmark` 一律等该批标注冻结后（`truth_frozen_at` 写入）再跑。

**顺带拿到一条独立佐证**：建管委预算的历史产物里写着
`BUD-105 T3=3286618082.20, T5=493761082.20`，差额 = 279,285.70 万元，与方案
§MR-4 记的基线差额**精确一致**——该数字现在有三个独立来源（方案原文、本轮
benchmark 重放、2026-06 的生产作业产物）。

另外这 27 份历史作业的 `mode=dual, use_ai_assist=true` 而 `ai_findings` 全部为空，
与全系统审计「AI 零次成功」的结论一致（此处仅作旁证，不在本盘点范围内）。

## 四、方法与可复现

- 候选筛选：`uploads/` 全量 PDF（361）→ 文件名含「决算/预算/公开」→ 44 份

- 台账产物：`docs/B1_CANDIDATE_INVENTORY_20260928.csv`（逐份 SHA/路径/副本/
  页数/字符/年度/层级），清单表即由该 CSV 生成。

## 九、L1 标注底稿（方案 §3.2.3 的 L1 层，已生成）

方案 §3.2.3：L1 全量 = 结构完整性 / 文种 / 单位 / 年份 / 表清单 / 空表说明（0.5–1 h/份）。
这些**全是材料事实**，与引擎会报什么无关，所以不构成盲标污染——方案 §八 开放问题 3
也明确允许「我辅助产出标注草稿由用户复核」。

产物：`docs/B1_L1_DRAFT_20260928.csv`，**38 份**（32 份本机候选 + 6 份已登记；
golden 已有完整 golden.json/ANNOTATIONS.md，不需底稿）。每字段都带**出处**与**置信**：

| 字段 | 取值方式 | 置信分布 |
|---|---|---|
| 文种 | 文件名与正文一致 → 高 | 高 37 / 中 1 |
| 年度 | 文件名与正文一致 → 高 | 高 35 / 中 3 |
| 单位 | 文件名与正文首页都命中 → 高 | 高 38（无一需人工） |
| 表清单 | 15 个核心表标题的**文本层命中** | 全部有值（0 份「待人工」） |
| 空表说明 | 取自 §七 的表结构判定 | 全部有值 |
| **L2 资格** | 已登记且当前输出已公开 = 否；其余 = 是 | **是 32 / 否 6** |

**用法**：你把每行当「待确认」而非「答案」——置信高的扫一眼即可，置信中的回原文核对；
`复核结论 / 复核人 / 备注` 三列留给签字后的定稿。

**⚠️ 表清单这一列的强度要说清楚（自检时报废过一版）**：

- 它只是**文本层命中**，不是表格实体清点——说明章节与目录里也会提到表名，所以
  「都命中」**不等于「表都印了」**。条件性表格是否真存在，要看 §七 的表结构判定
  （那才是硬信号：政府性基金表 28 份存在 / 10 份连表都没有）。
- 首版这一列用的是**部门预算的旧表名**（「收支总表」等），而单位预算模板的真实表名是
  「财务收支预算总表 / 收入预算总表 / 支出预算总表 / …」——于是 27 份预算的表清单
  **全缺三张总表**，且因为「全都一样缺」而看不出异常。改用真实表名后由 8/10 → **10/10**。
  这是本盘点第二次栽在「假均匀」上（第一次是 §七 的关键词窗口）：**当一组结果整齐得
  不像话时，先怀疑判据，再相信数据**。

> 诚实边界：本底稿**不包含任何 L2 内容**（勾稽复算、表文逐项、文内一致性、同比口径），
> 那 20 份仍须人工深标（2–3 h/份）。
