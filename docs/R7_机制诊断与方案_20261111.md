## 一、R7-01 声明组边界必须约束真正参与计算的操作数

### 实际输入 / 中间对象 / 全部消费者
输入（同一主体甲局、2025 年）：
- A `绩效自评的2025年度项目53个，评级结果如下。绩效评级为"优"的项目50个，其余评级均为0个。` → 应 fail `=`
- B A + `相关评级材料如下：其他材料中的示例，绩效评级为"良"的项目3个。` → 应仍 fail `=`（示例 3 不得计入）
- C `…53个，其中，绩效评级为"优"的项目50个。` → 应 pass `>=`
- D C + 同一材料标题下 `良10个` → 应仍 pass `>=`（示例 10 不得计入）

中间对象：`total`（自评总数）、`stop`（下一总数/任务切换）、`ratings`（本组评级数量）、
`declarations`、`parts`、`computed`、`cancelled`、`evidence_end`、`refs`、`scope_compact`。

消费者清单（当前全部使用 `total.end()..stop` 大范围）：
`ratings`、`declarations`、重复/身份校验（`rating_proof`）、`parts`、`computed`、
构成判定 `complete`、取消项目 `cancelled`、`evidence_end`、`refs`（证据跨度）、
`scope_compact`（部分/完整/无条件声明）。

### 最早失败层
声明组的**数量操作数提取**：`_declaration_attracts_group_counts` 只在布尔判断处截到材料
标题，而 `ratings/parts/computed/evidence_end/cancelled` 仍用 `total.end()..stop` 全集。
所以 B 中材料示例 3 被并入 50 凑成 53（漏报），D 中示例 10 被并入 50 凑成 60（误报）。

### 最小方案（不新增句式，不改口径）
在 `check_performance_counts` 内先确定**本组数量范围** `group_end`：
1. 起点 = `total.end()`；
2. 先按现有规则扣除任务切换（`switch`）；
3. 再在 `[total.end(), stop)` 内找第一个不同披露对象标题（`资料/材料/清单…如下`），
   `group_end = 该标题起点`；没有则 `group_end = stop`。
之后 **所有消费者统一使用 `[total.end(), group_end)`**：`ratings`、`declarations`、
`rating_proof`、`parts`、`computed`、`complete`、`cancelled`、`evidence_end`、`refs`、
`scope_compact`。声明识别不再各自截断（材料标题已在范围之外）。
组外的数字不进入本组；不借来凑平、不制造矛盾；如未来需要检查其他组，作为独立关系另立。

## 二、R7-02 金额列角色由原件栏目身份确认，统计只作辅助

### 实际输入 / 中间对象 / 全部消费者
控制原件 `mixed_amount_source_mixed.pdf`（无编码列，表头 `收入项目/金额/支出项目/金额`）：
```
本年收入合计 100   本年支出合计 100.50
年初结转和结余 200 年末结转和结余 199.50
总计 300           总计 300.00
```
对照 `mixed_amount_source_decimal.pdf` 仅把左侧写成 100.00/200.00/300.00。

中间对象：`_learn_column_roles` 的 `roles/codes`、合并侧 `_row_identity_and_numbers`
（按列位）、原件侧 `_parse_lanes`（编码集合 + 车道状态 + 日期短语）、
`_row_grounding_mismatches`（行级对账）、`reconcile_auto` 的 missing/extra 聚合。

消费者：合并侧身份与金额、原件侧编码判定与日期跳过、行级对账、聚合差异、verdict。

### 最早失败层
列角色学习的**证据顺序**：当前只看"3~7 位整数在该列占比 ≥50%"；mixed 原件左金额列
100/200/300 全部整数 → 被固定为 `code`；另一列有小数使金额守卫不触发。角色错 →
合并侧把金额当身份、原件侧当金额 → 虚假 missing_numbers 与 row_missing_on_page → 正常
产物 0 PASS/1 GAP。

### 最小方案
1. **表头/栏目身份优先**：从合并表的表头行（全文本行且含表头词）学习每列角色：
   `编码/科目编码` → code；`金额/决算数/预算数` → amount；`项目/名称` → label。
   同列多行表头按"code > amount > label"取最强证据。表头明确为金额的列，
   统计不得覆盖（mixed/decimal 两件的两金额列均为 amount）。
2. **统计只作辅助**：无表头证据的列才用整数占比 + 金额守卫（R5/R6 行为保留：
   守卫触发时两侧共同退回同一套形状规则，保持对称）。上下级编码结构（3/5/7 位
   类款项层次）作为辅助核对项写入诊断，本轮不作为必需判据。
3. **行级对账改为逐行身份约束**：删除"页级存在性"式 grounding（同页其他行出现同一
   数值即可满足，不能证明本行正确）；改由**身份+序列逐行比对**承担——合并行按
   身份找到原件记录并逐位比较金额序列，数值出现在同页其他行不满足本行；
   另补**反向覆盖**：原件存在、合并视图缺失的数据行 → `row_missing_in_merged`。
4. 年份/日期规则收窄为唯一形态：年份数字**仅当后随"年度"单元**时视为日期短语
   （真实"2025 年度…"元信息不算金额）；"2025 年末结转和结余"保留为金额。
   不再需要"金额列是否含年份形态值"的表级开关（R6 控制的本质是"年度"才是日期单元）。
