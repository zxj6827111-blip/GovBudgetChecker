## 1. 修改摘要

### 唯一运行目录与版本显示

- 新增 `src/engine/rule_registry.py`，运行时统一从 17 条预算、57 条决算、8 条通用 Python 规则读取实现、执行顺序和文种范围；动态读取规则模块，规则增删能反映到义务台账。
- `src/engine/pipeline.py`、`src/services/engine_rule_runner.py` 和义务台账改用同一目录路由与查询规则编号，规则未知时仍只执行通用规则。
- 规则目录导出实现类、文种、关联义务和财政事实迁移状态；新增管理员只读 `/api/rules/engine-catalog`，版本接口增加运行目录、策略版本和目录条数。

### 统一金额及比例政策

- 新增 `src/engine/rule_policy.py`：固定 `v3_3_portable`、金额容差 `0.5 万元` 和比例容差 `0.1 个百分点`，金额硬错误阈值按 `max(舍入包络, 0.5)` 计算。
- `classify_amount_diff` 增加 `within_policy_tolerance` 状态；超显示舍入包络但不超过 0.5 万元时按政策通过，并保留差额。超过 `max(E, 0.5)` 才返回 `mismatch`。
- 接入预算 T1/T3/T8/T9 勾稽、预算表文金额、决算说明金额、三公跨表比较、功能分类表文比较、文内重复披露及绩效阶段金额等已有 Decimal/包络比较点。
- BUD-111、CMM-007、V33-234 和完成率复算改用 0.1 个百分点绝对容差，不再以旧 0.5pp/相对 1% 放大政策阈值。零分母与单位问题仍由各自规则判断。
- 修订既有测试契约：不再把 0.004～0.08 万元差异作为确定性错误样例；保留并加强超过 0.5 万元的实际硬差异正例。

### 检查回执

- `CheckReceipt` 扩展义务编号、执行依据、事实迁移状态和策略版本字段。
- 正式分析在义务台账形成后，为每个已声明的义务/规则 checker 生成回执，映射六态、挂接对应 finding ID，并记录配置容差。
- 当前生产规则仍消费旧 `Document` 结构，所以回执明确 `evaluation_basis=legacy_document`、事实 ID 留空、`fact_migration_status=pending`；缺执行回执或缺实现记 `insufficient_data`，不推断通过。

## 4. 对规则、接口、存储和历史兼容的影响

- 两个生产 Python 规则入口及检查义务目录共用 `rule_registry.py`；规则顺序不变。
- 管理员规则版本端点仍分别显示 YAML 规则配置与 Python 运行目录；目录版本明确二者不是同一来源。
- 新增规则目录只读接口，不写入规则或用户数据。
- `CheckReceipt` 是增量 JSON 字段；回执在分析结果 `meta.check_receipts` 下输出，旧分析快照不回填。
- 金额比较仍使用 `Decimal` 与动态显示包络；规则政策阈值取更大值，不降低已有保护。百分比政策由绝对百分点阈值执行。
