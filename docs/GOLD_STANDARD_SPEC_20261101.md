# 决算审校金标准制作规范（2026-11-01）

> 目的：建立一套**不看系统输出、只看原 PDF** 的标准答案，用来实测本系统的
> 误报率、漏报率和人工工作量。之后每次改规则、改取数、并补核，都拿这套答案
> 比对，证明“误报不增、漏报不增”。
>
> 分工：**本地 DeepSeek 做初标** → **Claude 审核**（机器核验 + 抽查原文）→
> **用户仲裁**分歧。只有审核通过并冻结的条目才算金标准。
>
> 与既有规范的关系：沿用 `docs/B1_ANNOTATION_SPEC_L1L2_20260930.md` 的盲标纪律
> 和四态思想；本规范新增“逐项检查结论”（不只标问题，也标每项检查是否成立），
> 这样才能测出“系统说通过、实际有问题”的静默漏报。

## 一、样本

清单：`docs/GOLD_STANDARD_SAMPLE_20261101.csv`（33 份，固定随机种子抽样，不得自行替换）。

- 来源：`~/Desktop/预决算信息收集/决算测试上海市/{2022,2023,2024,2025}`（2026-11-01 由
  `~/Desktop/决算测试上海市` 迁入，33 份 sha256 复核不变），`path` 列为相对该目录的路径；
- 每年 3 份部门决算 + 5 份单位决算，同年不重复主管部门；2025 年因 GS-2025-01 按封面实为
  单位决算，另补 GS-2025-09（部门决算），共 9 份；
- CSV 带 UTF-8 BOM（便于 Excel 打开中文），程序读取须用 `encoding="utf-8-sig"`；
- `kind` 列是抽样配额用的预判，**材料口径以封面为准**（见 §三.D 裁定 R2），二者不一致时按封面标并在 `note` 说明；
- `sha256` 列必须与实际文件一致，不一致立即停止并报告。

## 二、红线（违反任一条，该份作废重做）

1. **盲标**：只能读 PDF 原文。禁止读取 `uploads/`、`outputs/`、`corpus/`、数据库、
   系统页面或任何本系统产出的检查结果；禁止参考“系统报了什么”。
2. **原文为准**：所有数字、文字证据必须**逐字摘自 PDF**（含原有千分位、单位、标点），
   不得转述、四舍五入或“修正”。
3. **不猜**：原文看不清、表格错位、跨页断裂、取不到唯一数值时，结论写
   `cannot_determine` 并写明原因，**不得**按“大概率没问题”写 `pass`。
4. **每条结论都要有证据**：页码 + 原文摘录 + （涉及计算的）完整算式。
5. 一份材料一个输出文件，处理中断须从头重做该份，不得拼接两次输出。

## 三、标注内容

每份材料标三部分：**A 基本信息**、**B 固定检查清单（逐项给结论）**、**C 自由发现的问题**。

### A. 基本信息

| 字段 | 说明 |
|---|---|
| `report_kind` | 固定 `final` |
| `material_scope` | `department`（部门决算，含所属单位汇总）/ `unit`（单位决算） |
| `fiscal_year` | 封面年度 |
| `organization` | 封面单位全称（逐字） |
| `pages` | PDF 总页数 |
| `tables` | 九张核心表：表名（逐字）+ 起始页 + 状态 `data` / `empty_with_note` / `missing` |
| `sections` | 九个说明章节：标题（逐字）+ 页码，缺失写 `missing` |

九张表与九个说明章节的名单见 `AGENTS.md`「决算公开规则」第 1、2 节。

### B. 固定检查清单（每项必须给结论，一项都不能跳过）

结论只有四种：

| 结论 | 含义 |
|---|---|
| `pass` | 已按原文取到全部数值并核对，成立 |
| `defect` | 已核对，确有问题 |
| `not_applicable` | 本材料确实不涉及（须写依据，如“第 20 页写明本单位无政府性基金预算财政拨款收支”） |
| `cannot_determine` | 取不到数值或原文无法判断（须写原因） |

|---|---|---|

| GS-S02 | 九个说明章节齐全，正文有“第X部分”标题 | |

### D. 已定裁定（试标审核后写入，后续全部材料照此执行）

| 编号 | 情形 | 裁定 |
|---|---|---|
| R1 | 多级加总的舍入累积（如项各差 0.01，到款叠加成 0.02） | 按**参与加总的末级项数** n 计舍入包络 `(n+1)×0.005` 万元，在包络内记 `pass`，`note` 写“舍入累积”及各级差额；超出包络记 `defect` |
| R2 | 部门决算 / 单位决算的判定 | 以**封面**为准：封面有“部门决算”→ department；只写“××年度决算”→ unit。文件名不是材料内容，不作依据，也不因文件名与封面不一致报问题 |
| R3 | 目录与正文标题只差“的情况”“情况”之类模板措辞（如“其他重要事项说明”与“其他重要事项的情况说明”） | 不算不一致，GS-S03 记 `pass`，也不进自由发现 |
| R4 | 同一问题已在检查清单里记为 defect | **不再**写进 `free_findings`，避免重复计数；自由发现只放清单之外的问题 |
| R5 | 同一错误在文中出现多处（如单位名称漏字） | 记一条，`note` 写明**全部出现位置**（页码与次数），不得只写部分 |
| R6 | 两处口径不同、无法判断谁对（如三公说明“车辆保有量”与国有资产“共有车辆”数不同） | 不写进 `free_findings`；写进 `gold/DISPUTES.md`，由用户裁决 |
| R7 | 只能依据文件名、目录外信息或推测才能成立的问题 | 不报 |
| R8 | 材料照抄上海市官方决算模板原文的措辞（第 2 轮审核加入；第 4 轮起按**材料所属年度**的模板判定，模板在 `gold/templates/`，2025 年用 2024 模板） | 不报。年度差异见 `gold/templates/README.md`（三公表名、部门决算正文“第二部分”已由 DISPUTES D2 裁决为 A：照当年模板写的不报）。已知：“国内公务接待支出XX万（含外宾接待支出XX万元）”前一处无“元”；目录“十一、其他重要事项说明”与正文“…的情况说明”；单位模板的“本部门建立了如下预算绩效管理制度”；“所属各预算单位…公务用车保有量”（措辞本身不报；保有量与资产部分车辆数不同见 DISPUTES D1）；名词解释“三公经费”条“…和公务接待费。其中:因公出国（境）费…”的半角冒号；国有资产部分“单价100万元（含）以上设备”（门槛，不是金额，不计入小数位）；第八节“政府性基金预算财政拨款收入XXX万元，**支出收入**XXX万元”（各年模板都这样写，第 5 轮加入）。模板**待选项**未选（“小于（大于）”“增长（下降）”）、**占位符**未填（“上海市XX局”）不属本条，仍按模板残留报 |
| R9 | 格式类问题：千分位缺失或用全角逗号、金额/百分比小数位不是两位（含“0万元”“11.4万元”“44.7%”）、中文语境用半角冒号、标点连用、双小数点 | 每份材料**每类只记一条**，`occurrences` 列出**全部**出现位置（页码 + 逐字原文），审核会用程序全文扫描核对条数。范围只限文字部分（第一、三、四部分）；第二部分决算表各页整页不计，含表下“注:”。小数位以“数字 + 万元/万/元/%”为锚，整数（“0万元”“100%”）也算，年份不算。千分位只看**金额**：科目编码（如 20808、2080506、31021）、电话与热线号（如“12345”）、人数次数台数（“7104人”）、百分比（“7550%”）都不算 |

| R13 | 表格勾稽判 defect 之前（第 4 轮加入） | 用与取数脚本**不同的办法**（逐行读页面文字）列出该类/款下的全部编码行，确认没有漏行、差额不等于某一行的金额，再判 defect；`values` 要列全所有行 |
| R14 | 提取的文字看起来缺了一段（第 5 轮加入，如 GS-2025-03 第 28 页：PyMuPDF 只读出页尾的第九节，页面上第七节后半和第八节都在） | 判“缺节、中断、缺数量要素”之前，先渲染该页看图，并用 pdfplumber 再读一遍。图上有就按图上内容判，**不算缺失**；从这类页摘的 quote 在 `values` 里加 `"source": "pdfplumber"`，核验时改用 pdfplumber 文本比对。每份材料先逐页比两个提取器的汉字数（PyMuPDF 比 pdfplumber 少 20 字以上或不到 80%）找出这类页 |
| R15 | 逐项说明写“决算数大于（小于）预算数”，但数字方向相反（第 5 轮加入） | 记 GS-N09 defect。原因本身自相矛盾（如“减少的原因是人次增加”）仍作自由发现“语句不通” |
| R16 | 增长率要用“本年数 − 增减额”倒推上年数才能复算（第 5 轮加入） | 本年数、增减额各按 ±0.005 取舍入区间，算出增长率上下限；正文值在区间内记 `pass`，`note` 写“舍入差”和区间；超出才 defect。例：GS-2023-03 接待费 6.20/(7.42−6.20)，区间约 503.7%–512.8%，正文 508.09% 成立。**两个条件都要看**：正文值落在区间内，或与复算值相差不超过 0.1 个百分点（计算口径的绝对容差），任一成立记 `pass`；两者都不成立才 defect。第 7 轮例：GS-2024-08 接待费 0.31/(1.17+0.31)，区间 20.61%–21.28%，正文 20.78% 成立；GS-2024-07 财政拨款 2.44/735.93=0.33%，正文 0.24%，差 0.09 在 0.1 容差内，记 `pass` |

| R18 | 本单位无“三公”经费支出（第 5 轮加入） | 模板做法是：三公表保留、空白，表下只有通用“注：”；第七节写“XX年度无‘三公’经费财政拨款支出”。照此写的 GS-S01 记 `pass`，GS-T07、GS-N07 记 `not_applicable`。第七节没有这句才报 |

| R20 | `note` 与现状一致（第 5 轮加入） | 删掉或改判某一项后，所有引用它的 `note` 同步改：`note` 里写的自由发现编号必须存在，“见 GS-XXX”所指检查项必须仍是 defect。冻结后自由发现编号不再重排；已冻结的文件（有 `truth_frozen_at`）脚本一律不得重写 |

| R24 | 序号体例（清单 E-04、E-05；第 6 轮加入） | 同一列表序号体例须一致（“1、”与“3.”不混用）、编号不跳号不重号。每份一条自由发现（类别“其他”），`occurrences` 列全。不同列表各自一种体例不算混用（如第一部分“主要职能”用“1.”、第三部分逐项用“1、”） |
| R25 | 自由发现里“只能靠读文字才发现”的一类（错别字、漏字多字、语病、重复词等；第 6 轮加入） | **尽力而为，不要求穷尽**，不进漏报率分母，指标里单列（可报“该类自由发现的系统命中数”，不报漏报率）。例如“年初预算104.75万元”漏“为”，其他材料同样漏“为”的未必都标出。**要求穷尽**的只有能用程序全文扫描的类：R9（千分位、小数位、半角冒号、标点连用、双小数点）、R22、R21、R24、R28、GS-S03/S04 的名称与标题比对 |
| R26 | 同比、完成率：基数为 0 时的百分比（第 6 轮加入，第 8 轮定稿，第 9 轮细化；如 GS-2023-07 因公出国费、GS-2025-04 公务接待费） | **基数为 0（含按“本年数 − 增减额”倒推后为 0）且分子不为 0** 时，不得写百分比；写“增长100%”“增长100.00%”等任何百分比，记 GS-N07 同比子项 defect；只写“增加 X 万元”、写“上年为 0、不可比”或“增长—%”的不报。**基数和分子都是 0**（上年 0、本年 0；预算 0、决算 0）时，写“0%”“0.00%”不算缺陷：没有误导，模板也要求三项各写一个完成率或同比（用户 2026-11-03 裁定；系统规则 V33-TREND 按 AGENTS R004 报这类，计为误报）。AGENTS R004 的适用范围按此收窄为“预算为 0 而决算大于 0 却写出完成百分比”。R16 的舍入区间以分母非 0 为前提，不适用于这一条；即使按倒推数的 ±0.005 舍入留出余地，上年数至多 0.01，增长率也在 600,000% 以上，“100%”不可能成立 |
| R27 | 标题（含目录）里的单位名称、年度笔误（如目录“202 年度”、标题“生态环境局局”；第 7 轮加入） | 记 GS-S04（名称、年度）；若因此目录与正文标题不一致，另记 GS-S03，两项都是 defect，`note` 互相指明 |
| R28 | 文号（清单 D-04；第 7 轮加入） | 文号年份必须用六角括号“〔2024〕”，写成“[2014]”“【2024】”等记一条自由发现（类别“标点”），`occurrences` 列全（页码 + 逐字原文），要求穷尽（程序全文扫描：`[一-鿿]{1,12}[\[【（(]年份[\]】）)]\d+号`） |
| R29 | 表格单元格因列宽被截断的科目名称（第 7 轮加入，如 GS-2023-07 第 12 页“机关事业单位基本养老保”、GS-2023-08 第 10 页“机关事业单位基本养老保险缴费”少“支出”） | 不算与逐项说明名称不一致：同一材料别处的表（收入、支出决算表等）或说明里完整出现的名称为准；只有该科目在本材料所有表里都没有完整形态时才拿表里的写法去比。不另报“名称显示不全” |
| R30 | 差异原因写得泛泛（第 9 轮加入，如“根据年度实际情况，经费支出有所增加”；用户 2026-11-03 裁定） | 只要写了一句原因就算写明原因，GS-N09 不判 defect；只有完全没写原因、或原因与增减方向矛盾（R15）才判。系统按“原因仅重述结果”报这类，计为误报 |

计算口径：金额统一换算为万元；容差 0.01 万元，多项加总允许 `(n+1)×0.005` 万元的舍入包络；
百分比容差 0.1 个百分点；元→万元须按四舍五入到正文精度，截尾或进位错直接 defect。
只差在舍入包络内的，结论写 `pass`，在 `note` 注明“舍入差”。

### C. 自由发现的问题

清单以外看到的问题（错别字、多字漏字、重复词、模板残留、标点、病句、科目编码与名称不符等）
逐条列出。规则同上：页码 + 逐字原文 + 应为什么。拿不准的写 `confidence < 0.7`。

**不要**为凑数硬找问题；没有就留空数组。

## 四、输出格式

目录：`gold/GS-2024-01/annotation.json`（每份一个目录，目录名 = `sample_id`）。
文件为 UTF-8 JSON，结构如下（示例数字为虚构）：

```json
{
  "sample_id": "GS-2024-01",
  "sha256": "与清单一致",
  "annotator": "deepseek-<模型名与版本>",
  "annotated_at": "2026-11-02T10:00:00+08:00",
  "basic": {
    "report_kind": "final", "material_scope": "department", "fiscal_year": 2024,
    "organization": "上海市人力资源和社会保障局", "pages": 37,
    "tables": [{"name": "收入支出决算总表", "page": 8, "status": "data"}],
    "sections": [{"name": "一、收入支出决算总体情况说明", "page": 18}]
  },
  "checks": [
    {
      "check_id": "GS-T07",
      "verdict": "defect",

          "label": "三公经费决算数合计",
```

字段要求：

- `checks` 必须恰好包含 §三.B 的 24 个 `check_id`，顺序不限；
- 检查项整体 `verdict`：任一子项 defect → defect；否则任一子项 cannot_determine → cannot_determine；全部 pass → pass；
- `values[].quote` 是 PDF 中**逐字**出现的文本（金额连同千分位原样），评审会用程序在该页文本里查找；
- `formula` 必须能复算；占比写出分子、分母；算式中每个数字都要在 `values` 里有原文出处（R10）；
- `free_findings[].category` 取值：错别字 / 多字漏字 / 重复词 / 模板残留 / 标点 / 语句不通 / 编码名称不符 / 单位错误 / 格式 / 其他；

  `page`/`quote` 填第一处；
- `annotator` 写明实际模型与版本（如 `deepseek-v3.2 via qoder`），`SUMMARY.csv` 的 `elapsed_min` 填实测分钟数。

## 五、建议做法（给 DeepSeek 的执行提示）

1. 用 PyMuPDF（`fitz`）逐页提取文本，用 pdfplumber 提取表格；**每页单独处理**，避免上下文过长丢信息；
2. 先做 A（找表、找章节、定页码），再按页码定位做 B，最后通读全文做 C；
3. 表格跨页时把续页行接上再算；表格解析错位时回到页面文本核对，仍对不上就写 cannot_determine；
4. 每份完成后自检：24 项都在、每个 quote 能在对应页文本里找到、每个 formula 复算无误；
5. 33 份全部完成后，输出 `gold/SUMMARY.csv`：每份一行，列出各结论计数与耗时。

## 六、审核流程（Claude 执行）

1. **机器核验（每份 100%）**：sha256、24 项齐全、quote 在页面文本中逐字存在、formula 复算、
   单位换算与容差判断。任一不过 → 退回该份。
2. **原文抽查**：
   - 所有 `defect` 与 `free_findings`：100% 回 PDF 核对；
   - `pass`：每份随机抽 5 项回 PDF 核对；
   - `not_applicable`、`cannot_determine`：100% 核对理由是否成立。
3. **退回标准**：一份材料抽查错误 ≥2 处，或出现编造 quote → 整份退回重做；
   同类错误在多份出现 → 修订本规范后批量重做。
4. **分歧**：审核人与初标意见不一致、且原文确实两可的，列入 `gold/DISPUTES.md`，由用户裁决；
   裁决前该项记 `cannot_determine`，不计入指标。
5. **冻结**：全部通过后在每份 `annotation.json` 写入 `reviewed_by`、`truth_frozen_at`，sha256 记入
   `gold/FROZEN.csv`。冻结后才允许用本系统跑这 33 份做比对；冻结后任何修改须记录原因并全量重算指标。
   冻结前，下列**全集扫描**必须在该份上跑过且与标注一致（第 6 轮定；批次 3 之前的材料靠审核人事后补扫，
   其中 GS-2022-04、GS-2024-04、GS-2024-05 因 R21/R22/R23 被扫出新条目，已撤销冻结）：
   ① 两个提取器逐页比对汉字数（R14）；② R9 五类与 R22 的程序全文扫描，与 `occurrences` 逐条一致；
   ③ R21 口径措辞；④ R24 序号；⑤ GS-S03 的目录与正文标题逐条比对，含第一部分（R23）；
   ⑥ GS-S04 单位名称近似变体与年度扫描；⑦ T05、T08 另用逐行文字法重算（R13）；
   ⑧ 所有 `note` 引用（自由发现编号、“见 GS-XXX”）与现状一致（R20）；
   ⑨ R28 文号扫描；
   ⑩ **回归比对**：每次改脚本、重跑未冻结的文件后，把新旧 `annotation.json` 逐检查项、逐自由发现做差，
   只允许出现本轮要求的改动。第 6 轮重跑就曾把已裁决的 D2（GS-2022-08、GS-2024-02、GS-2025-09 的 S01/S02）、
   R12（GS-2024-02 的 W01）、R16（GS-2024-08 的 N07）又改回缺陷。

## 七、冻结后算出的指标

| 指标 | 算法 |
|---|---|
| 误报率 | 系统正式问题中，对应金标为 pass / not_applicable 的比例 |
| 漏报率 | 金标 defect 中，系统判为通过或未报的比例（**静默漏报**单列）。自由发现里 R25 所列“靠读文字才发现”的一类不进分母，单列命中数 |
| 待核实命中率 | 系统“待核实/未能自动核对”中，金标为 defect 的比例（衡量噪声） |
| 人工工作量 | 每份材料需人工处理的条数（必须处理 + 待核实） |
| 自动化覆盖 | 24 项中系统能自动给出 pass/defect 的比例 |

`cannot_determine` 的金标项不进入误报/漏报分母，单列统计。
这些数字即“现状基线”，第二阶段每项改动都必须在此基线上证明漏报率不升、误报率不超目标。

## 八、工作量估计

每份约 28 页、24 项检查：DeepSeek 初标每份约 20–40 分钟（视速度），审核每份约 15 分钟。
建议分三批交付：先交 4 份（每年 1 份）试标 → 审核修订规范 → 再交剩余 28 份。
