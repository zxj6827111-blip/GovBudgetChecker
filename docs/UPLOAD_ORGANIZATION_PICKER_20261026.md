# 上传材料归属选择优化

只缺组织归属时，文件操作显示“确认归属”，打开最大宽度 720px 的侧栏。优先展示预检相关候选；没有候选或候选不符时，通过组织名称、已维护的关键词、部门/单位层级和市区管理范围搜索。完整归属路径、材料层级和当前文件作用范围始终可见。

## 数据与确认边界

- 候选来自原始预检的 `suggestions`、`binding_decision.candidates` 和原因中的候选 ID，与服务器可选目录求交集；候选名称和层级以目录为准。
- `scope_undetermined` 时展示候选部门及其真实直属单位，最多展示六个候选；其余组织通过搜索查找，不根据名称伪造本级单位。
- `GET /api/organizations?stats=none&purpose=upload` 标记 `selectable` 并返回已维护的 `keywords`。只可见的祖先用于路径，不能用于上传归属。
- 上传专用目录不采用前端本地完整目录兜底；缺少服务端可选标记的节点不可选。默认组织导航接口保持原有契约。
- 不自动选中候选；取消、Escape 不保存。只保存当前文件的人工选择，批量预设不能替代范围不明材料的逐份确认。
- 人工确认仍通过原上传中心适配器计算状态、生成上传参数；后端原件冲突、权限及上传校验继续执行。附带的完整路径和层级只用于显示，提交归属仍使用唯一组织 ID。

## 验证与运行边界

- 后端：`tests/test_organization_import_contract.py`，15 项通过，包括授权祖先不可选、关键词及普通目录兼容。
- 前端：上传中心适配器回归、TypeScript、定向 ESLint、颜色守卫通过。
- 独立生产构建：45 个页面生成成功。
- Chrome：原上传页及新选择器共 24 项回归通过，覆盖请求中的真实 `org_unit_id`、候选不自动选择、同名市区组织、简称搜索、取消与焦点恢复、逐文件确认、目录重试及 390px 窄屏。
- 浏览器业务接口使用测试拦截；这些结果不代表真实 PDF 识别正确、材料已上传或数据库持久化验收。

前后端需同步更新。实施时检查发现本地 3000 和 18743 提供旧版本，已使用隔离构建验证，未重启这两个现有服务，也未覆盖现有 `.next`。当前运行的旧服务不会自动加载源码修改。
