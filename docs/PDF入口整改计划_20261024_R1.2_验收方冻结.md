## 3 整改要求

### 3.1 第一批：结论可靠性（必须全部完成）

#### IR-01 统一自动归属决策

**现状。** 自动绑定有三条路径：

- 上传：`_auto_match_organization`（[upload.py:256](../api/routes/upload.py)）
- 批量重匹配：`rematch_job_organizations`（[runtime.py:3569](../api/runtime.py)）
- 修复缺失关联：`repair_missing_job_organization_links`（[runtime.py:3865](../api/runtime.py)）

它们的问题分别是：

- 上传预检直接调用 `suggest_matches`，绕过了 `OrgMatcher.match` 里“不绑市/区级”和“平局不绑”的保护（[org_matcher.py:56-73](../src/services/org_matcher.py)）。
- 冲突检查读的是 `organization.get("name")`（upload.py:52），而序列化候选的字段是 `organization_name`（upload.py:105），所以自动路径上的名称冲突检查实际不生效。
- 后两条路径完全不做封面冲突检查。

#### IR-02 名称等价比较

**现状。** `_organization_binding_conflict` 的逻辑是“任一方包含另一方即视为不冲突”，所以下属单位材料可以挂到上级部门。另一方面，括号内容的含义差别很大：

- 组织库里括号中出现过的有：“本级、本部、机关、部门、单位、筹、林业、上海”，以及各种别名。
- 其中“本级、部门、单位、筹”是身份标记；“中国（上海）自由贸易试验区”“上海市绿化和市容（林业）工程管理站”里的括号是正式名称的一部分；“上海市水务局（上海市海洋局）”里的括号才是别名。
- 已渲染核实，原件封面写的就是“中国（上海）…”“…（林业）…”，是现有的封面抽取把括号内容删掉了（IR-12）。

**必须做到：** 区分“格式归一”和“身份等价”两层，并写成单元测试。展示名称一律不变。

1. **格式归一**（始终执行）：NFKC 归一，去空白，统一全角/半角括号。
2. **身份等价**：两名称格式归一后完全相同，即为等价。在此之外，只允许以下几种有依据的等价：
   - **别名**：组织库条目写作“A（B）”时，以 A 或 B 匹配该条目，前提是 A（或 B）在组织库中**唯一**。别名必须来自组织库条目本身或其 `keywords`，不得把任意括号内容当别名删掉。
   - **身份标记**：本级、本部、机关、部门、单位、筹，必须双方一致。“X本级”“X（本级）”“X本部”三者互相等价，但都**不**等价于“X”。“X机关”是独立单位。
   - **正式名称组成**：如“（上海）”“（林业）”，不得删除。
   - **地区前缀**：开头的“上海”与“上海市”可以互认，前提是互认后在组织库中唯一。
3. **包含关系不算等价。**
4. 每次判定记录命中的是哪一条规则。身份标记和正式名称组成的保护优先于通用括号别名解析，不能先拆出 A 或 B 再绕过限制。IR-01 第 5 条在决策层处理，不给比较器增加“X 等价 X（本级）”的特例。

**测试：**

- `divergent_true_wrong` 的 2 例和 7 例上级部门错绑必须判为不等价。
- “X（本级）”对“X”不等价。
- “中国（上海）…”对“中国…”不等价（原件本来就带括号）。

**验收：** A2、A4。

#### IR-07 缺失、零、空白、横线：取数语义

**现状：**

- 交通委 2022 报出 10 条 V33-119“行横向校验失败：合计(X) != 分项之和(0.0)”，以及 V33-122“政府性基金表应为空（因总表无数据）”，而这份材料其实有 62,203 万元政府性基金收入。

**必须做到：**

1. 盘点所有直接读原始表格行、并做加总或比较的规则，在整改记录中列表，写明每条规则的处理方式。至少包括 V33-119、V33-122、V33-240、V33-005、V33-120、V33-241、V33-002。

3. 单元格取值按原格状态分别处理，不得混同（R1.1 把空白和横线分开规定）：

   | 原格状态 | 处理 |
   |---|---|
   | 明确数字，包括 `0.00` | 按原值计算 |
   | 确认的空白格 | 判定“空白”时，只看单元格内框以内（扣除边框线宽），排除边框、底纹填充、合并单元格的占位；内框以内不得有文字字形、图像或非边框矢量，以防“文字层丢字”被当成空白。在此基础上，只有适用的模板约定（见第 4 条）允许时，才在指定计算中按 0 处理 |
   | 明确横线（“-”“—”等） | 横线本身就是内容，不套用“无内容”条件。保留横线原文，按适用模板对横线的定义处理；没有定义时按未知处理 |
   | 不适用 / 未披露（“无”“不适用”“/”等） | 一律不按 0 计算 |
   | 漏读、列未映射、内容无法确认 | 保持未知，不计 0 |

4. **模板约定按地区、年度、表种和适用单元格范围配置**，每条写明来源（文件名称、发文机关、文号或链接）。暂时没有对应文件的，可以作为经用户确认的业务约定启用，但必须标注其性质为“用户确认约定”（U-5）。不得把一地一年的约定默认推广到所有年份和全部九张表。**当前未记录用户对 U-5 的明确批准；批准完善计划或启动第一批不等于批准“空白按 0”。** 无适用依据且未获明确确认的范围保持未知。配置记录来源性质、范围和启用依据；测试显式约定只在隔离测试生效，不成为生产默认值。
5. **原始值始终保留为空白或横线。** “按 0 参与计算”是带依据的计算解释，要记录所依据的约定；不得改写成“原件明确写了 0”，证据展示和导出里也必须显示原件的空白或横线。
6. 依赖“未知”值的检查输出取数不足，列出相关单元格。依赖“空白按 0”得出的问题，要在问题描述中写明哪些格按空白计 0、依据哪条约定。
   **验收方适配补充：** U-5 未批准时，若仅凭明确数值已能看出关系不平、而差额可能由未知的空白格承担（如华东政法大学 2025 收入决算表 205 行：明确分项之和 40,425.80，合计 87,161.66，“其他收入”空白），该检查须以 `manual_review` 问题报出已知金额、差额和相关空白格，写明“差额可能由空白格造成，请核对原件”，**不得只记取数不足**，否则真问题会被空白语义压掉。不涉及空白的不平照常按规则严重度报出。
7. 共用的取值判断放进同一个辅助函数，不要在规则里各写一套。

- 单元格内框里有未进入文字层的字形或矢量时，不判为空白。
- 有边框和底纹的空白格不被误判为“有内容”。

另 1 份，上海市文化旅游公共服务和人才服务中心 2022，**原件表格本身是平的**（如 207 行 3,480.24 = 3,359.34 + 120.90），但第二列表头漏印了“财政拨款收入”，系统认不出这一列，列身份配错。这一份降级是对的，而且存在独立的结构证据（表头无法解释该列）。

这类“整列系统性出错”的每行差额各不相同，正好落入现行判据，被当作列映射错误压掉了。基线管线对这几份材料的收入决算表**没有报出任何问题**，只在复核原因里留了一句“合计与分项系统性对不上 N 个金额格待复核”。同一份材料里，性质相同的支出决算表错误却照常报了 error。

这 5 份说明：能区分“原件错”和“读错”的是结构证据，而不是算不平的行数多少。

**必须做到：**

1. **算术不一致本身不得作为降级依据。** 它只能触发结构复查。
2. 只有存在**独立的结构证据**时，才可以认定列映射有误并降级。结构证据包括：
   - 表头路径无法解释该列；
   - 该列数字的横向位置落在表头列带之外；
   - 单元格内含两个金额或两个编码；
   - 数据列数与表头列数不符；
   - 与续页的列边界不一致；
   - 竞争的几何候选给出了不同的列归属。
   降级时把证据写入事实和回执。
3. 没有结构证据时，**不再仅因算术不一致而降级**；原有的单位、来源、列身份和读取完整性门禁继续生效，因其他原因不可信的事实照旧不准入。通过这些门禁的事实，由规则照常报出勾稽问题。同一张表多行同类不平时，**按表汇总为一条问题**，列出全部行和差额（不只前 3 例），并写明“可能为原件整列漏填或错位”。
4. 无论是否降级，原始差额和问题线索都必须完整保留在问题清单或复核项中，并能导出。
5. 结构证据是“表头缺失”时，表头缺失本身是原件问题，要作为待人工复核问题报出。不得替原件补列名。
6. 不再按表的大小设门槛。R0 提出的“少于 6 行不降级”作废。

**测试：**
- 5 行 3 处独立错误：不降级，照常报出。
- 20 行、某列明细全为 0 而合计非 0：不降级，按表汇总报出。
- 列表头空白、数字其实平衡：有结构证据，降级，并报出表头缺失。
- 现有的整列错位用例：有结构证据，仍然降级。

## 5 验收方法

验收方对交付提交执行以下步骤。为避免验收期间工作区继续变化，验收方会先把交付提交导出为独立副本，再在副本上执行：

1. 全量 `pytest -q`，与 `baseline/pytest_full.log` 对照。
2. `verify_intake_remediation.py collect`：
   - 全量 2,363 份做归属；
   - 2,258 份去重原生 PDF 做解析；
   - R1.1 清单中的 23 份做既有端到端；
   - 按冻结 T0 清单核对逐格、归属及扫描样本；R1.1 逐格文件数记录为 9，类别和独立文件数以清单核对为准。
   - R1.2 新增绑定边界、A6r 证据断言、E1 单列资产版本及结果，不改写以上历史数量。
3. `compare --batch <N>`，以冻结基线为准，逐条判定 PASS / FAIL / REVIEW / LATER。LATER 表示属于后续批次，只记录现状、不计入失败。
4. 审阅 `git diff 6d62a7c0..<交付提交>`，重点检查第 0.2 节列出的禁止做法。
5. 逐条复核 REVIEW 项。
6. 执行 E1 并核对 A6r 原因与证据。未适配进 `compare` 的条目单独出结果；本批任何硬性条目未执行，均不能宣布本批验收通过。

### 5.1 判定原则

1. **“绑定正确”和“自动化效率”分开验收。**
   - 绑定是否正确，只由独立核实过期望结果的样本判定，是硬性条目：A2 已知个案、T0-B 封面核实样本。
   - “与文件名一致”不是正确归属的依据。
   - 未绑定数、封面主体为空数等是效率目标。达到目标判 PASS；未达到判 REVIEW，逐例说明原因。有充分理由转待确认的，不应为了数量指标被迫绑定。
   - 每份待确认材料须有规定原因码及可核验证据（A6r，硬性）。全量检查记录完整性与可自动核对的条件，逐例复核新增、变化或无法自动证明的原因；反证成立即 FAIL。A2/A4 必须绑定样本仍须绑定。
2. **已独立确认正确的结论不得回退**，一律为硬性条目。范围包括：T0 **对应批次预期**内的取值与准入结论、已知个案（A2、C7、C8、D）、本版新增绑定边界与 E1、全量测试 0 失败、解析耗时。
3. **数量类指标只作观察**，判为 REVIEW。范围包括：进入规则数、待复核数、单份变差、基线事实丢失、整份阻断、算术降级、改绑、年度与目录冲突。修复错误放行后，数量“变差”可能正是进步，但每一处变化都要在整改记录中逐例说明原因。**说明不成立或没有说明的，由验收方判为 FAIL。**
4. 目录年份是语料整理时的归档，不保证正确。年度冲突逐例核对原件，以原件为准。
5. 身份确实不明的材料允许保持未确认，但要给出原件依据。
6. 指标或样本口径确需修改时，由验收方先修订并冻结，执行方不得自行调整。
