# Golden Corpus 标注模板（第一期，可直接安排填写）

- 制定日期：2026-08-29
- 目的：解决「规则全绿只能证明没有静默失败，不能证明该查出来的都查出来了」——
  语料 = **真实材料 + 每份材料应检出问题的标准答案**，用于度量规则（以及将来的 AI）
  的召回率（该查出的查出比例）与精确率（报出的里正确的比例）。
- 与规则文件的关系：`rules/v3_3.yaml` 是**评分标准**（检查什么、怎么判），本语料是
  **考卷 + 标准答案**（拿真实材料去考规则）。两者互补，缺一不可。

---

## 一、命中判定口径（先定死，避免算 recall 时扯皮）

对一份材料的每条标注（期望检出），与系统实际输出对比：

| 判定 | 条件 |
|---|---|
| **命中（true positive）** | 实际输出存在一条 finding：`rule_id` 相同 **且** 页码相同。文档级规则（BUD-001，页码填 `DOC`）只比 rule_id。 |
| **部分命中（half credit）** | `rule_id` 相同、页码相差 ≤1 页（表格跨页断裂常见）。统计时记 0.5。 |
| **漏检（false negative）** | 标注了但系统没有任何同 rule_id 的输出（含页码不符超过 ±1 页）。→ 拉低召回率 |
| **误报（false positive）** | 系统报出了标注里没有的 finding（同材料同 rule_id 维度对比）。→ 拉低精确率 |

公式：`召回率 = 命中 + 0.5×部分命中) / 标注总数`；`精确率 = 命中 / (命中 + 误报)`。
先按材料分组算，再出总数；BUD-001 文档级规则单独一行统计（与 B1 口径一致）。

## 五、首期范围（材料 20–50 份，只标以下 6 条高频规则）

依据 793 个历史任务的真实命中分布排序：

| 2 | V33-120 | 明细表勾稽关系与层级校验（表 2/3/5） | 94 | warn |
| 3 | CMM-004 | 收入/支出总表类款项编码与金额镜像一致性 | 91 | warn |

材料配比建议：**至少 1/3 是"没有问题或问题很少"的正常材料**（否则精确率会被
"系统多报"的单边样本扭曲，测不出误报率）。

## 六、材料从哪来（现成池）

1. `samples/good|bad/`（4 份，bad 即已知问题版，最省标注成本，**第一批先标它**）；
2. 244 个 done 历史任务（系统的输出可先抄下来当"预标注"，人工只做确认/修正）；
3. UAT 阶段复核员经手的真实材料（边用边沉淀）。

## 七、填写流程与质检

1. 每份材料：通读 → 对照六条规则逐个排查 → 填 labels.csv → 回填 manifest 状态。
2. 存疑条目（拿不准该不该检出）照填，置信列写 `存疑`——度量时剔除，不进分母。
3. 抽检：每 10 份抽 1 份由第二人复核；不一致的条目讨论后定稿。
4. 标注只答「应该检出什么」，**不要**参考系统当次输出后再抄——会污染精确率度量
   （系统报了才标 = 永远测不出漏检）。正确顺序：先盲标，再与系统输出对比。

## 八、度量对接

- 第一期手工算即可：拿 `labels.csv` 与系统输出（status.json 的 `result.rule_findings`）
  按第一节口径对比，填进一张汇总表。
- 数字稳定后（≥3 批），把对比脚本化（输入 corpus 目录 + uploads 目录，输出
  recall/precision 报告），先进 CI 作**观测指标**（只报告不拦人），稳定后再设阈值。
