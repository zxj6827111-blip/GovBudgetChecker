## P1-1：当前指标无金额时，仍跨子句借用其他指标金额

位置：`src/engine/rules_v33.py:1303`～`:1305`，`_extract_amount_from_segment` 第二遍 `_pick_best(restrict_to_kw_clauses=False)`。

新版先限定逗号子句，但当该子句没有金额时，仍主动取消边界。独立复现：

```
基本支出60万元，项目支出未披露。
```

取“项目支出”实际返回60。应为未取得金额。

真实V33-103复现输入：

- 收入决算表：本年收入合计100.00、财政拨款收入100.00，单位万元。
- 对应收入决算情况说明：“本年收入合计100万元，财政拨款收入未披露。”
- 实际结果：返回`[]`，没有未完成状态。

这说明算法将前项100补给未披露财政拨款，伪造“核验完成”。若财政拨款表值不同，还会产生无说明证据支撑的差异。

整改：禁止用相邻指标金额补当前缺失值；没有可验证归属时返回未知并由消费者上报deferred。单子句兼容不需要通过取消多子句边界实现。若支持逆序或跨标点表达，应有具体语法/指代证据，不能仅依赖距离。补“未披露/空白/无法识别、前项有数字”的实际V33-103/104/105测试，验证可靠项仍检查、未知项不造数。

## P1-2：T1/T4严格取数仍越过字段边界，空收入被支出补位

位置：`src/engine/budget_rules.py:632` 的 `_extract_t1_strict`，尤其`:643`、`:650`遍历到整行末尾；`_extract_t4_strict`的`:556`、`:562`有相同扫描方式。

真实BUD-101输入：

```
部门财务收支预算总表，单位：万元
项目     | 预算数 | 项目     | 预算数
收入总计 | 空白   | 支出总计 | 100.00
```

实际返回`[]`。收入取数跳过空白和“支出总计”标签，把右侧100.00作为收入；支出也取100.00，于是产生假平衡。

这不是归一化或包络算法错误，而是StrictValue之前已经选错来源单元格。采用StrictValue不能自动提供字段边界；该辅助函数同时被其他消费者使用，因此应在取数层关闭。

整改：按表头列组或字段对应单元格取值，遇到下一指标边界停止；绑定值为空或无效必须保留原状态，不扫描后续其他字段补数。同步检查T4同型函数及BUD-101/105/107消费者，补缺收入、缺支出、无效文本、明确0、正常、真实差异以及partial findings双顺序用例。
