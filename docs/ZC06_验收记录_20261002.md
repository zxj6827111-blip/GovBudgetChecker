## 1. 修改摘要

- `IssueItem` 增加可选 `check_relation_id`、`fact_ids`、`evidence_ids`。只有检查关系及事实 ID 均明确时，AI/规则结果才可能配对；标题相似、页码接近、标签相同或金额接近不参与合并。
- 重写 `src/services/merge_findings.py`。一对一明确关系才合并；同一关系出现多候选时标为歧义并保留所有来源。匹配后的展示代表固定取确定性规则 finding。金额/指标操作数精确不同或严重度不同会生成冲突记录，冲突不会同时计入 agreement。
- `MergedSummary` 增加关系组、AI 候选 ID、人工复核 ID 和合并策略版本。AI 独有项不计入正式 `merged_ids`/合并总数；关系冲突保留完整 AI/规则 finding，原始 finding 桶和冲突均可追溯。
- `ReviewReport` 把 AI 独有候选、关系冲突放入待人工复核；正式问题集合按新策略只读取非候选、非歧义代表。复核生命周期可读候选并标记为非正式项。
- 前端双模式合并视图遵循新 `merged_ids`；AI 独有候选留在 AI 来源视图及 ReviewReport 人工复核栏，不混入正式合并计数。
- 新增 `src/services/ai_candidate_contract.py`：离线契约只允许模型提出候选事实字段、已知事实/证据 ID 和语义不确定项；不接收严重度、期望值/实际值、公式或容差。逐项校验，坏候选被拒绝时保留同批合法候选。

## 2. 必须验证对照

| 验证项 | 结果 |
|---|---|
| 标题、金额相同但无事实 ID | 不合并；规则 finding 保持正式代表，AI 项进候选/待复核 |
| 检查关系和事实 ID 相同，标题和页码不同 | 仍按身份配对；规则侧为唯一代表，关系保存 AI/规则两侧 ID |
| 同关系、事实金额不同 | 进入 value conflict；不计 agreement；规则代表保留 |
| 同关系、严重度不同 | 进入 severity conflict；不会抛枚举异常或整批回退 |
| 同一关系有多条 AI 候选 | 标记 ambiguous；所有相关 finding 保留并进入人工复核，不贪心配对 |
| AI 仅有候选、无规则对应 | 不进入正式合并集合；在候选/待复核集合保留 |
| AI 引用未提供的事实/证据 ID | 该候选单独拒绝；同批其余有效候选保留 |
| 模型提交 severity 或金额判定结论 | 严格 schema 拒绝额外字段 |
| ReviewReport 与复核集合 | AI 候选不计入正式问题；冲突和歧义明确进入人工复核 |
