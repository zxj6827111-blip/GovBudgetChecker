## 1. 问题陈述

当前前端与原型图在**信息架构、导航形态、视觉规范**三个层面均不一致：

- 原型图为左侧双分组竖向导航（8 项），当前实现为顶部横向导航（6 项）+ 左侧组织架构树；
- 原型图缺失的「质量管理」「规则与版本」两屏在当前实现中完全不存在；
- 当前实现围绕「确认问题 → 生成整改包 → 导出归档」组织，原型图围绕「处理队列监控 → 质量门禁 → 发布门禁」组织，产品视角不同；
- M1–M4 后端产出的质量字段（`page_coverage` / `evidence_status` / `formal_issue_total` / `rule_version` / `engine_version`）**在前端引用次数为 0 或仅有类型声明**，用户无法据此校准对结果的信任度。

## 2. 需求（已与项目负责人确认）

| # | 决策 | 含义 |
|---|---|---|
| 1 | **b** | OCR 成功率、Golden Corpus 回归趋势、P0/P1 召回率、问题精确率共 4 项**本轮不做**（底层能力未实现，无数据源）。质量管理页只呈现有真实数据的指标 |
| 2 | **a** | **原型图为准**，严格按 8 项导航重建；组织树降级为工作台内筛选器；整改包/导出归档另开第 9 个入口 |
| 3 | **a** | 无设计稿的 4 屏（处理队列独立页、任务历史、规则与版本、系统设置）按原型图设计语言自行推导 |

### 不可违反的约束

- **严禁展示未经度量的准确率或任何虚构数字。** 本轮整改用四个里程碑消除"虚假成功"，UI 不得反向引入。
- 不得回退 M1–M4 成果：年份识别失败返回 `None` 不得兜底；不得绕过质量门禁；`count_formal_findings` 为正式问题数唯一口径；日志脱敏与 `/metrics` 鉴权不得削弱。
- 交付时门禁不低于第 0 节所列基线。

## 3. 背景（研究结论）

### 3.1 数据供给盘点

| 原型图元素 | 后端现状 | 结论 |
|---|---|---|
| 待人工复核 / 正在处理 / 处理失败 / 本周已完成 计数 | `/api/jobs` + status | ✅ 可用 |
| 页面覆盖率 | job meta `page_coverage` | ✅ 后端有，前端仅 `app/lib/uiAdapters.ts:47` 类型声明，从未渲染 |
| 质量状态徽章 | status + conclusion 可推导 | ✅ 可用 |
| **页面缩略图栏** | `/api/files/{job_id}/preview?page=N&scale=0.5` 支持任意页与缩放 | ✅ **已有，无需新增后端** |
| PDF 单页 + bbox 高亮 | `problemPreview.ts` 按百分比换算坐标 | ✅ 已实现 |
| unknown 比例 / 证据完整率 / 错误率 / 复核率 | `/api/metrics`（M3 建成） | ✅ 可用 |
| 耗时 / 页数 / 问题数 | job meta + `formal_issue_total` | ✅ 可用 |
| **处理队列「当前阶段 + 进度%」** | 仅 `rule` / `ai` / `total` 聚合耗时 | ❌ **无 per-job 实时阶段与百分比，需补** |
| **失败阶段分布** | 未记录失败发生在哪个阶段 | ❌ **需补** |
| **最近活动流** | 有 `audit_log` 但未暴露 API | ❌ **需补** |
| OCR 成功率 / Golden Corpus / 召回率 / 精确率 | 能力未实现 | ❌ 按决策 1=b **本轮隐藏** |

### 3.2 架构障碍

1. `app/app/page.tsx` 直接 re-export `app/app/viewer/gbc-ui-demo/page.tsx`，后者是 **106 KB 单文件 monolith**（`PageId` 六态、`NAV` 六项均在其中）。在其中塞 8 屏不可维护，**必须先按路由拆分**。
2. 主色现为靛蓝 `#4f46e5`（`app/tailwind.config.ts`），原型图为墨绿。换 token 会影响所有现有页面，需一次性统一并回归对比度。

### 3.3 测试面

- `app/tests/` 存在前端单测（如 `uiAdapters.status.test.ts`）。
- e2e 33 项依赖 `gbc-nav-${id}`、`gbc-detail-confirm`、`gbc-logo-home` 等 `data-testid`，**导航重建会破坏，需同步更新**。

## 5. 方案要点

- **渐进式替换，不推倒重来**：新建 `app/(workspace)/` 路由组承载 8+1 屏，`gbc-ui-demo` 保留至迁移完成后（Task 10）再删，避免中途不可用。
- **组件先行**：先按原型图规范建基础组件层，后续各屏复用，保证视觉一致性来自单一来源而非逐页手抄。
- **缺数据一律显式缺席**：不渲染假数；涉及未实现能力的卡片整块不出现，并在质量管理页列出"本版本未启用的指标及原因"，可追溯。
- **后端只补三项**：per-job 阶段与进度、失败阶段归因、活动流，均带测试。

## 8. 与本轮整改成果的关系

本计划**新增**了 M1–M4 未覆盖的用户侧价值：把后端已经诚实记录的质量信息（覆盖率、证据状态、规则版本、当前阶段）第一次呈现给审核员，使其能自行校准对结果的信任度。

同时**明确不做**的部分与整改结论一致：OCR 自动识别与 Golden Corpus 召回率度量仍是空白，故相关 UI 一律缺席而非填充示例数据。这一点在质量管理页对用户显式声明。
