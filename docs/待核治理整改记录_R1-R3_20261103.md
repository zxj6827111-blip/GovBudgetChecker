### R1 旧任务新旧字段判断

- 问题：前端用 `reason_codes` 是否存在判断旧/新结果；当前 API 会把旧任务的 `reason_codes` 投影成 `[]`，导致 56 份旧任务全部丢失 V33-227 提示。
- 修改：`isLegacyResult` 改以 `legacy_coverage_terms` 的缺失/`null`（旧）与列表（新，含 `[]`）为契约。旧结果回退旧 `detail` 正则；新结果只读结构化原因码。
- 测试：
  - 前端 `projectedOldTask`：`reason_codes=[]`、`legacy_coverage_terms=null`、旧 detail → 保留 V33-227。
  - 后端 `test_old_task_projected_through_api_model_keeps_legacy_null_and_empty_codes`：真实 `build_coverage` → `ObligationReviewItem` 投影后确认旧任务 `legacy_coverage_terms=None`、新任务 `[]`。
  - 复核方脚本重跑：`old_projected_lost=0`、`old_without_reason_codes_retained=56`、`current_new_tasks_retained=56`（`<EVID>/r1r2/old_task_frontend_results.json`）。

### R2 FIN_04 同源消费方迁移

- 问题：FIN_04 同源提示仍用 title/detail 正则；结构化字段不变而 detail 改写后提示丢失。
- 修改：新增 `sameSourceEvidenceText`。旧结果沿用第一阶段 title/detail 语义；新结果优先使用 DH-03b 保留的“规则说明”冻结业务文本，只有冻结文本缺失时才回退完整 detail。FIN_04 表身份同时识别中文表名、简称与 `FIN_04_fiscal_grant_total` 表代号。
- 语义边界：有冻结业务说明时只读冻结文本，避免前言提到 FIN_04、但业务原因实际是基金表的误报；不把所有同表检查泛化为同一原因。
- 测试：
  - 前端 FIN_04 用例：旧 detail、改写为表代号的 detail 均保留同源提示；冻结说明只含基金表时不得误报；旧任务（`legacy=null`）仍按旧语义提示。
  - 160 份真实记录逐份比较旧/新 FIN_04 提示：`checked=160`、`mismatches=0`（`<EVID>/r1r2/fin04_old_vs_new.json`）。
