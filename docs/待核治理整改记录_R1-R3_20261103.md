- 问题：前端用 `reason_codes` 是否存在判断旧/新结果；当前 API 会把旧任务的 `reason_codes` 投影成 `[]`，导致 56 份旧任务全部丢失 V33-227 提示。

- 测试：
  - 前端 `projectedOldTask`：`reason_codes=[]`、`legacy_coverage_terms=null`、旧 detail → 保留 V33-227。
  - 后端 `test_old_task_projected_through_api_model_keeps_legacy_null_and_empty_codes`：真实 `build_coverage` → `ObligationReviewItem` 投影后确认旧任务 `legacy_coverage_terms=None`、新任务 `[]`。

### R2 FIN_04 同源消费方迁移（严格契约）

- 问题：R2 首版仍从 `detail` 提取“规则说明”并在缺失时回读完整 `detail`；同时把简称/表代号正则用于旧任务，扩大了第一阶段匹配范围。
- 修改：
  - 旧结果（`legacy_coverage_terms` 缺失/`null`）：逐字保留第一阶段匹配器——空表侧只认 `detail` 中的“财政拨款收入支出决算总表”，总表侧认 title/detail 中的“财政拨款收支总表/财政拨款收入支出决算总表”。
  - 新结果（列表，含 `[]`）：**禁止读取 `detail` 及“规则说明”**；FIN_04 身份只认持久化结构化字段：`missing_operands`/`candidates` 的 `table_code=FIN_04_fiscal_grant_total`，或 `blocked_by[].ref` 中的 `FIN_04`/`FIN04` 身份；总表侧可用稳定表题识别。
- 语义边界：
  - 仅改 `detail` 或仅改“规则说明”不改变判断；
  - 旧任务简称/表代号不触发新提示，只有完整表名保留旧语义；
  - 不把所有同表检查泛化为同一原因。
- 测试：
  - 三个边界均有前端单测：仅改 detail、仅改规则说明、旧任务简称/表代号。
  - 复核方 `fin04_contract.ts` 重跑：`detail_changes_hint=false`（两组）、`old_semantics_expanded.short_title_actual=null`、`table_code_actual=null`。
- 已知损失：`RB-2024-U07` 的新结果 FIN_04 身份只存在于 `detail`，现有结构化字段为空；严格实现下新提示为 `null`（旧提示为 `OBL-CROSS-FISCAL-TOTAL`）。已保存最小复现并提交字段契约冲突：`docs/契约冲突_FIN04同源依据_20261103.md`；该损失状态为**待验收方裁决**，不表示方案 A 已批准或阶段验收通过；未自行增加文案回退或新字段。
