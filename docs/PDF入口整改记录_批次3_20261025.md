## 3. IR-15 人工补录整行整表

### 3.1 后端

- `CorrectionChange` 新增 `table_rows`（append_rows / replace_data_rows）与 `table_identity`（表种确认 + 原件缺表头标记）。
- `manual_cell_overlay.py`：
  - 新增行只写数据区；`replace_data_rows` 保留原表头，删除其后的数据行再重建；
  - 同一行命中两个及以上表头词时拒绝，提示“原件缺表头只能确认缺失，不能替原件补列名”；
  - 金额列（已映射列 + 数据行中出现过数字的列）只接受数字；前两列编码/名称不按金额列误判；
  - 表种只能在原表为 `UNKNOWN` 时确认；已识别表种与提交表种不一致时拒绝；
  - 审计记录写入 `processing_manifest.manual_rows` / `manual_table_identity`：record_id、actor、reason、created_at、evidence_ids、物理页与 bbox、mode、row_indices、table_code、original_header_missing；
  - 补录摘要进入 `config_fingerprint`（`manual-overlay-v2`）与 `parse_run_uid`；同样的补录产生相同解析身份，改动补录产生新身份；
  - 未确认列身份的金额格不把事实提升为 verified。
- `affected_check_ids` 增加表实例 UID 到其下 `fact_uid` 的前缀匹配（只匹配显式依赖字段），提交响应返回受影响子检查清单。

### 3.2 前端与 e2e

- “读取校正”页签新增：
  - “新增行”“整表重录”编辑器：按 `|` 或 Tab 分列，超过表宽即拒绝；
  - 表种确认下拉 + “原件缺表头”复选框（仅 UNKNOWN 表显示）；
  - “框选原页区域”：先跳到表格所在页，再在 PDF 页面上拖拽框选；框选结果用 MediaBox 逆变换换回解析坐标，作为补录证据位置；
  - 待提交列表展示“确认表种/新增 N 行/替换数据行 N 行”。
- e2e `review-corrections.spec.ts` 新增完整流程：确认表种 → 框选原页（真实鼠标拖拽）→ 新增行 → 整表重录 → 提交；断言三类 changes 的表种、mode、rows 与框选位置。**2/2 通过**。

### 3.3 未完成：检查级增量重算

- 已实现：受影响子检查清单精确到表下事实，提交响应返回 `affected_checks`，前端据此提示复核范围。
- 未实现：重分析仍整份重跑（重新解析 + 全量规则）。规则共享同一事实上下文与跨表回执，局部重算需要合并旧回执、问题编号和汇总状态；当前架构没有这层能力。
- 影响：补录后不会漏算，但受影响范围之外的检查也会重新生成，效率不是最优；IR-15 第 5 条只部分满足。

## 4. IR-16 扫描件 OCR 实测

详细报告：`outputs/intake_remediation_20261024/ir16_ocr_measurement/REPORT.md`。

- 47 份材料（11 份整份扫描 + 36 份含无文本页）全部调用成功，0 错误。
- 34 个选中页是真实空白页（无内嵌图、OCR 0 block），13 个是扫描页；36 份混合材料中只有 2 份存在真正的无文本扫描页，其余无文本页都是空白页。
- 文本模式（150 DPI、顶部 700px 裁图）：9/13 扫描页有实质文本（11–78 块、4–49 个金额 token，块平均分 0.7392–0.9990，其中 7 页 ≥0.9692），实质页中位耗时 24.3 秒/页；4 页无金额（封面/低分）。
- 结构模式探针（同样 700px 裁图，3 页）：2 页 `mapped`（逐格分数最低 0.9366/0.9468，低于 0.98 候选阈值），1 页 `ambiguous`（`cells=0`，`missing_or_mismatched_cell_geometry`）；两页 mapped 的表头第二行只恢复 2 列，与数据行 9 列不一致。150 DPI 全页结构模式曾返回 502 并导致容器自动重启，未作为常规路径。
- 人工核对 2 页关键金额与裁图一致；但只有 2 页样本，不构成准确率。
- OCR 图像页门控（默认开启）：无文本且无图像/墨迹的页跳过并记入 `blank_pages`；`OCR_IMAGE_GATE=false` 可关闭。该变量已进入处理身份指纹，并在 `.env.example` / `docker-compose.yml` 声明。
- 未测：错字率、错数率、错列率、漏行率、人工处理量。原因是没有逐格人工真值；IR-18 的标注完成后才能统计。
