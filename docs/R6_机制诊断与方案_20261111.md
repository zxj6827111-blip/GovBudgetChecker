## 一、R6-01 评级声明与同组数量的归属

### 数据流（现状）
`check_performance_counts`：
1. `totals`/`stop`/`switch` 界定本组自评范围（下一自评总数或任务切换）；
2. `scope_compact = text.compact[total.end():stop]`；
3. 三个独立布尔决定关系类型：`partial_declared`（部分限定 + 披露谓词同子句，R4）、
   `complete_declared`（全部/所有限定 + 披露谓词同子句，R4）、
   `declares_ratings`（无条件"评级…如下"，R5 收紧为名词白名单 + **句内**引出数量）；
4. `comparison_basis`/公式/结果由三者派生。

### 最早失败层
`_introduces_rating_counts` 把"声明引出的数量"截止在**第一个句末（。；）**。
"评级结果如下。绩效评级为'优'的项目50个，其余评级均为0个"——声明与同组数量被句号
分隔，`declares_ratings=False`，回落 `disclosed_lower_bound`，53>=50 被 当 pass。
句内截止是为排除材料清单引入的，但它把"标点"当成了"组边界"——标点不改变
主体/年度/任务，不是组边界。

### 同型分支核查
- 限定词路径 `_qualifier_governs_ratings`：子句界定只影响"限定词是否带披露谓词"，
  `explicit_period`（全部…如下。）仍 fail 是因为 `complete_declared` 不依赖引出数量——
  该路径无需改。
- 材料排除：R5 的名词白名单（结果/情况/等级）在声明识别处生效，必须保留。
- 数量提取/证据/门禁：不在失败层内，不动。

### 最小方案：声明组归属（不新增句式条件）
无条件声明（"评级/评价（结果|情况|等级）如下/见下"）打开一个**声明组**，组内向后
（本组 scope 内）扫描实际评级数量（`_RATING`）。组终止符只有两个：
1. 本组末尾（已有 `stop`/`switch`：下一自评总数、其他评价工作切换）；
2. **不同披露对象的标题**（"资料/材料/清单 … 如下"）——其后的数量属于其他材料，
   不吸入本组（任务书明确要求）。
句号、分号、括号、断行**不终止组**（主体/年度/任务未变）。组内找到数量 →
`declares_ratings=True` → 完整等式；找不到 → 不声明，回落部分列举不等式。
材料/资料清单的排除路径（R5 名词白名单）保持不变。

### 影响面与验收关系
仅 V33-250 关系识别分支；不改数量提取、证据、门禁、容差。
验收：R6 六断言（complete_colon/period/semicolon/explicit_period=1 fail `=`；
partial/materials=0 pass `>=`）+ R2～R5 全部旧正反例（归档前/后/逗号/括号/句号、
合法部分列举、真实范围冲突、材料标题排除）。

## 二、R6-02 列/车道角色贯穿

### 数据流（现状，标出丢失点）
```
PDFParser 产物（table_fragments/logical_tables 保留列位）
  → _logical_view_with_provenance（rows/cells 保留列位）            【列位仍在】
  → _codes_from_rows：输出**数值集合**                              【丢失点1：列位压平】
  → _row_identity_and_numbers：[c for c in cells if c] 去空列        【丢失点2：列位再次丢失】
  → _parse_lanes：扁平 token 流；日期分支"年份数字+下 token 以年开头" 【丢失点3：邻词代角色】
  → 原件侧/合并侧共用上述规则 → 同失互相抵消
```
`year_amount_source.pdf`：金额列含 2025，右侧科目"年末结转和结余"以"年"开头，
日期分支把 2025 当日期短语删除；两侧同删，行身份还被拼成
"年初结转和结余年末结转和结余"，验收对象集合为空 → 零比较 PASS。

### 同型分支核查
`_row_identity_and_numbers` 去空列（列位丢失）、`_parse_original_page` 纯数字行
年份过滤、`reconcile_auto` 聚合（按数值集合）——均改为从同一份列角色取依据。

### 最小方案：列角色学习一次、贯穿三个消费者（不做大重构）
1. `_codes_from_rows` → `_learn_column_roles(merged_rows)`：输出
   **逐列角色** `{列位: code|subcode|amount|label}` + 编码列数值集合 + 表级事实
   **"金额列是否含年份形态值"**。判定规则：
   - code：该列 ≥50% 非空值为 3~7 位整数（候选），且金额守卫不触发
     （守卫=候选列会吃光全表数字列 → 学习失败、全部退回金额，R5 保留）；
   - subcode：该列 ≥50% 为 1~2 位整数且左邻列是 code（拆码款/项）；
   - amount：该列含数值（年份形态也算数值——角色跟列走，不跟形态走）；
   - label：其余。
2. 合并侧 `_row_identity_and_numbers(cells, roles)`：按**列位**取角色——
   code 列 → 类码、subcode 列 → 款/项码、数值（含 2025）→ 金额、文本 → 标签；
   不再做形状猜测。去空列只跳过空串，列位角色不丢。
3. 原件侧 `_parse_lanes`：仍为扁平流（原件文本天然无列位），但角色依据改为：
   - 编码=来自角色的编码集合 + 车道状态规则（R5 保留）；
   - **年份形态数值是否是金额，由"金额列含年份形态值"这一表级角色事实决定**：
     含 → 一律金额；不含 → 仅"2025 年度…"日期短语单元跳过（任务书明确
     "真实'2025年度…'元信息仍不能算金额"）。
     不再使用"下 token 以年开头"的宽泛邻词条件。
4. 行级 grounding（角色贯穿到原件核验的落点）：每条合并行把角色指定的
   编码/金额原值按列序对回原件该页 token 流，缺失或乱序 →
   `row_grounding_mismatch` → GAP。验收对象集合由列角色决定，独立于
   车道解析的形状猜测，候选视图无法反向删减原件对象。
5. `_row_identity_and_numbers` 去空列保留（只影响 token 顺序），角色按原列位
   附加到 token，不再丢。
