### 1.2 最早失败层与根因

- 边界提取：`src/engine/native_final_disclosure.py:1470`
  `r'(?:资料|材料|清单)[^。；]{0,10}如下'`。
- 同一边界在声明扫描处再次独立出现：`src/engine/native_final_disclosure.py:1593`。
- `_Text.compact` 做 NFKC 后，中文分号 `；` 已变为 ASCII `;`，空白（含换行）被删除；
  所以 `[^。；]` 实际只排除 `。`，可以跨 `,`、`;`、`(`、`)`。
- “材料已归档”的谓词是**归档**；“评级结果如下”的谓词是**如下**，对象是**评级结果**。
  现正则把两个子句拼成“材料…如下”，从“材料”处设置 `group_end`，后续真实评级数量
  全部落在组外；`ratings` 为空，`declarations` 也为空，二者数量相等通过校验，
  随后 `src/engine/native_final_disclosure.py:1482` 的 `if not ratings: continue`
  直接离开——**零问题、零回执、真实规则执行器 V33-250 记 pass**。

### 1.3 机制：披露谓词的最近对象绑定（不是分隔符补丁，也不是词表黑名单）

新增**唯一**的材料组边界函数（两个调用点共用，不再各写正则）：

```
_material_group_boundary(compact, start, stop) -> Optional[int]
```

判定步骤：

1. 在 `[start, stop)` 内逐个子句找披露谓词 `如下` / `见下`；子句边界是句末标点
   `。！？!?`（compact 已去空白，换行不构成边界）。
2. 对每个谓词，在同一子句、有限窗口内向前找**最近披露对象锚点**，取结束位置最近者：
   - 材料对象锚点：`资料` / `材料` / `清单`；
   - 评级对象锚点：`绩效?评级` / `绩效?评价` / `等级`（可带 `结果/情况/等级` 后缀）。
3. 只有**最近锚点是材料对象**时，该谓词才是材料清单标题；`group_end` 取材料锚点起点。
   最近锚点是评级对象（或没有锚点）时，`如下` 属于评级披露，不产生边界。
4. 区间内有多个材料标题时取最早一个；任务切换仍先按既有 `switch` 收窄 `stop`，
   边界函数只在收窄后的范围工作。

为什么这能同时满足两类反例，而不是“再补三个分隔符”：

- `材料已归档,评级结果如下` / `材料已归档)评级结果如下` / `材料已归档;评级结果如下`
  / `材料已归档。评级结果如下`：`如下` 的最近对象都是 `评级（结果）`，不是 `材料`。
  逗号、括号、分号、句号都不改变“最近对象”，所以四个变体一致不截断。
- `相关评级材料如下：其他材料中的示例，绩效评级为"良"的项目3个`：`如下` 的最近对象
  是 `材料`（`评级` 在其前，被 `材料` 盖过），仍是材料标题，示例数字不进入本组。
- `材料清单如下`：最近对象是 `清单`（同为材料类）；`评级资料如下`：最近对象是 `资料`；
  都按材料标题处理。
- 不引入“已归档”“归档”等词面排除；判定依据是谓词前最近对象，与具体动词无关。

### 2.4 角色如何决定、原件与候选如何独立核对

**候选侧（解析产物）**：

1. 仅当 `instance.table_code` 是 `NINE_TABLE_RULES` 中的已知表时，取
