## 仍须修正的两个问题

### 1. [P1] 去重先标记、后分类，导致未匹配模板的出口直接消失

`scratch/build_a01_comprehensive_ledger.py:199` 先把提前 Return 行放入 handled_return_lines，后续只有条件匹配若干字符串或特例才创建记录。如果未匹配，既没有记录，也不会被最后的 Return 扫描补记；因此“冲突为零”并不等于“出口完整”。

独立扫描所有注册规则的 apply 方法，排除嵌套辅助函数，发现以下 **7 个真实返回出口没有自身或直接父条件记录**：

| 规则 | 源码位置 | 真实条件/行为 | 应如何处理 |
|---|---|---|---|
| BUD-003 | budget_rules.py:1150 | 未识别 report_year 时返回 | 登记输入前提、不能核验年份的范围与目标状态 |
| BUD-109 | budget_rules.py:1818 | 未提取到 narrative_mentions 时返回 | 属于说明侧输入缺失场景，不能从底账消失 |
| V33-115 | rules_v33.py:2417 | 委派 `_apply_structured` | 这是合法委派路径，登记委派及结果来源，不机械标成缺数据 |
| V33-240 | rules_v33.py:3680 | 表行列宽不一致，跳过整表 | 源码明确指出跨页列布局漂移；应登记无法可靠核验的原因 |
| V33-241 | rules_v33.py:3836 | 表行列宽不一致，跳过整表 | 同上，不能因条件写成 `len(...) > 1` 而漏掉 |
| V33-227 | rules_v33.py:4619 | 未提取到 narrative_mentions 时返回 | 登记说明侧输入缺失的裁决 |
| CMM-003 | common_rules.py:448 | toc_count < 8 时返回 | 登记现有启用阈值及其适用/未决依据，不强行判为数据错误 |

其中 BUD-109、V33-227 的说明缺失及 V33-240/241 的列布局歧义，直接属于已批准的缺输入审查范围。不能因已经修好上轮列出的几条规则，就忽略其余规则的同类出口。

**修法：** 每个提前出口先形成带父路径的记录，再执行语义分类；未能分类的一律显式标记未决，不能静默加入 handled 后丢弃。或仅在已登记父路径后标记 Return 已处理。所有真实出口须有映射、合法委派说明或明确未决依据；这不意味着全部出口都应迁移为 insufficient_data。

### 2. [P1] V33-246 正常披露出口被错误指定为 insufficient_data

底账 `V33-246-B02`（rules_v33.py:5903）将 `if section_domestic: return issues` 标为 `to_migrate`、目标 `insufficient_data`、卡号 B04。

源码的 section_domestic 表示在三公章节中已经识别到国内接待批次/人次披露；该提前返回是避免对拆分段落重复误报的正常完成路径。此时没有理由仅因提前 return 就转未完成。若照底账实施，会把已完成检查降级为未完成，增加不必要的人工复核。

**修法：** 按当前规则定义，登记为披露条件满足后的正常完成出口。若认为识别逻辑需要增强，须另外列为有证据的未决问题，不得借本次底账整理直接改变已批准语义。
