## 操作顺序与可审查结果

1. 阅读第十七轮报告，复算最终服务回执和 SHA；失败/中断的试跑记录保留，不能纳入准入通过场景。
2. 实际保管、标注、独立复核和执行人员填写角色及授权附件。开发会话和脚本名不能代替真实人员。
3. 从官方来源选择新的完整原件，比对开发 SHA，独立检查近重复；完成八分层原件登记和至少 100 个真实缺陷组。
4. 人工标注适用分母、缺陷、可接受项、定位及分歧裁决，先封存真值，再冻结代码、配置、模型、评测器和覆盖层。
5. 独立执行者在同一冻结身份下跑两次全链及四格式导出，先保存结果，再按授权揭盲评测。
6. 记录 Gate A–F 的业务签收；精确率、召回、重大问题漏报、定位、证据真实性、确定性完成率和导出一致性分别达标才可正式验收。

交接准备命令（必须使用新的空输出目录）：

```bash
.venv/bin/python scripts/prepare_independent_acceptance.py \
  --output /absolute/path/new-intake \
  --known-development-root '/Users/zhangxingjin/Desktop/决算测试上海市'
```

提交附件后用 `--check-handoff /absolute/path/handoff.json --stage intake` 校验；
执行附件齐备后再用 `--stage execution`。退出码 0 仅证明已声明附件的结构/字节身份通过门禁，
不验证签名真实性，也不等于业务验收通过。pending 模板保持人员为空、真值为空、指标为 null。

原始扫描的技术准入须查看整份 PDF 的 OCR 物理页覆盖、失败页、有限 Worker 预算、
金额事实的原件/原页/原单元格绑定和真实区域复识别。局部有效金额不能被表述为整张表全部完成。
缓存校正须同时查看本次 `structured_ingest` 完成状态、实际缓存命中/JSONB provenance 读回、
当前数据库分析版本、原始金额事实和证据、原始 `corrections.jsonl` 及当前 FactContext。
