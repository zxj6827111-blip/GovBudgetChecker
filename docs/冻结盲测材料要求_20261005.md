# 冻结盲测材料要求与交付清单

日期：2026-10-05。对应第八轮复核 R8-04。此文件与空白模板已经准备好；真实材料、人工真值和正式验收尚未齐备，独立业务指标保持 null。

## 数量与独立性

开发集至少32份，盲测集至少32份，两套分别满足下表；混合材料额外标记 `mixed`，不能代替任一分层配额。

| 文种 | 组织 | 来源 | 开发最低份数 | 盲测最低份数 |
|---|---|---|---:|---:|
| budget | department | native | 4 | 4 |
| budget | department | scanned | 4 | 4 |
| budget | unit | native | 4 | 4 |
| budget | unit | scanned | 4 | 4 |
| final | department | native | 4 | 4 |
| final | department | scanned | 4 | 4 |
| final | unit | native | 4 | 4 |
| final | unit | scanned | 4 | 4 |

盲测至少100个由人工确认的真实缺陷组，按每份文档的 canonical 真值组身份去重；同一缺陷在文字、表格、多页有多个证据仍只算一组。建议 truth_id 加 doc_id 前缀以免串号。正常披露、允许取整和待人工复核样例也要标注，供误报判定；这些不计入100个真实缺陷。

真值组契约（R10-03整改）：优先采用显式 `truth_group_id`，没有时使用原样 `truth_id`；每条证据另有唯一 `annotation_id`。配额和指标均调用 `src/services/truth_grouping.py` 的同一函数。仅兼容完整匹配 `T<数字><单个小写字母>` 的历史证据面（如 T4a/T4b→T4）；其他英文尾缀保留原样。新材料统一显式写 `truth_group_id`，可以避免历史简写歧义。合法例：两个独立缺陷 DOC-001-income 与 DOC-001-expense 各自成组；同一缺陷两处证据共用 DOC-001-income 组、分别使用 A-001/A-002 标注ID。非法例：重复 annotation_id、用文件后缀拆分同一缺陷、在查看结果后改组以减少漏报。旧冻结标签保持原样，不为迎合结果改写真值。

两个集合原始 PDF 哈希不得重复；同一材料改文件名、改渲染方式、加 OCR 文本层、换年份标签均不能绕开独立性。旧开发集、已用于定位错误和调参的材料及本轮合成反例不能重新算独立盲测。近重复正文、同单位同年度版本应人工归组检查；目前脚本只检查精确 SHA 去重，需要额外提交近重复审查记录。

盲测由独立材料保管和人工复核人员冻结；开发者在规则、模型和阈值冻结前不查看盲测真值。提交真实复核人员标识、复核日期、分歧处理和冻结记录，不能填写示例姓名或用 AI 自动标签冒充人工复核。已经泄露给开发调参的盲测材料转开发材料，并从未见过的材料补足盲测配额。

## 每份材料的提交内容

| 文件/内容 | 要求 | 常见不合格情况 |
|---|---|---|
| `corpus/<doc_id>/<原文件名>.pdf` | 目录内恰好一个 PDF，保留真实原件，记录来源链接/获取时间/原件 SHA；可公开或获授权使用 | 仅提供解析缓存；多份 PDF 无法确定原件；生成合成材料冒充真实样本 |
| `golden.json` | doc_id、sha256、report_kind、truth_frozen_at、非空 reviewed_by、labels、applicable_sub_checks | 只有页码和问题描述；标签是在查看系统结果后补出的 |
| 人工复核记录 | 逐标注复核人、严重度、依据、分歧与最终决定；来源/年度/组织/文种独立确认 | reviewed_by只有占位名；没有复核日志 |
| 区域真值 | 缺陷标签的 physical page 对应 `page`，`truth_region.page/bbox`，原件可见原文 evidence，章节/表/格锚点 | 目录页码当物理页；框为整页；框和文本来自待测 OCR |
| 必查分母 | 完整适用关系、预期状态/不适用理由另有人工清单；`applicable_sub_checks`逐关系冻结 | 从实际执行回执生成分母；缺失关系被删出分母 |
| 回放与重复运行 | 真正生产链输出，主/重复回放、同源同配置同版本指纹和版本记录 | 手填规则结果；版本改变后仍宣称同版重复运行 |
| 四格式 | 同 analysis_revision 的实际 JSON、CSV、DOCX、PDF 下载，逐文件 SHA与规范报告指纹 | 只调用生成器；混合新旧分析版本；缺人决/回执/结论 |

`page` 使用1起始的物理 PDF 页。bbox 为原件 PDF points、左上原点 `[x0,y0,x1,y1]`，有序且在页面内；旋转/裁剪需记录转换依据。没有测得区域就留 null，并标记未完成，不能编造。脚本的精确命中要求认证通过、同页、交集至少覆盖真值区域面积的50%、候选框面积不超过真值框4倍；只有页码命中不满足精确定位门槛。

标签类型为 `defect`、`rounding_hint`、`manual_review`、`acceptable`。每条有唯一 annotation_id；前三类有 truth_id。defect 记录 expected_severity 和 allowed_rule_ids（或兼容旧 rule_id）、page、evidence、location_key/章节锚点与 truth_region。一个 truth_id 可对应多个独立证据标注，不能拆成多个缺陷增加召回分母。所有标签类别按人工判断冻结，不能把漏报改成 acceptable。

适用关系优先写 `{ "rule_id": "V33-103", "sub_check_id": "T2:fiscal_allocation:share_of_income_total" }`，字符串兼容形式是 `规则::子检查`。裸子检查或单冒号串无法确定关系。清单由人工从原件和规则义务确认；条件性项目写明适用依据，不把“无此项”直接认作漏检查。

## 冻结、运行与解封顺序

1. 材料保管人完成分层、SHA去重和近重复审查。人工先看原件独立标注，再交叉复核、解决分歧，冻结真值和必查分母。
2. 开发只使用开发集修规则/OCR/参数。记录提交版本；工作区未提交时还要全量源码和新文件 SHA 清单，单独 HEAD 不足以标识当前实现。
3. 冻结原件、golden、分层清单、适用分母、规则/OCR模型/配置、代码、依赖/镜像、评测器版本及哈希。生成签认记录，保管人再发放盲测原件给运行者。
4. 同一冻结版本跑两次真实生产链，保存回放、逐关系回执、trace、SQL、实际四格式下载和哈希；先固定输出，再由保管人解封真值评测。不得为通过门槛修写输出或真值。
5. 报告 TP/FP/FN、缺陷组匹配、八层统计、漏掉的高/重大问题、全部门禁与不可计算原因。失败后回到开发集整改；已解封盲测若用于调参，下一轮独立验收要更换未见材料。

## 四个真实服务场景

| 场景键 | 真实输入及验证 | 额外证据 |
|---|---|---|
| native_budget | 真实原生预算；登录→上传→API排队→独立Worker→PG→分析→下载 | 原件、任务/分析版本、入库与逐关系回执、实际四格式 |
| native_final_known_issue | 真实原生决算，含人工冻结已知问题 | known_issue_truth_id、实际检出及证据引用；不能只说存在任一报警 |
| scanned_budget | 真实扫描预算，可信OCR实际参与 | OCR模型清单指纹、真实请求/响应、逐格事实及原件认证；自动操作数为0不能核销可信晋升 |
| mixed_final_manual_correction | 含扫描部分的真实混合决算，人工校正后重审 | OCR、correction_id、前后不同analysis_revision、实际新算式/回执、reanalysis_status=completed、旧版隔离 |

所有场景使用真实 HTTP、独立 Worker、隔离 PostgreSQL，禁用内联回退。每个任务的 SQL 回执与 trace 用 job_id 对齐；数据库累计表计数不能冒充单任务事实数。API与Worker build_revision相同。保存原件/导出的真实路径及 SHA、trace_path、artifact_path/sha、真实 reviewed_by；通过布尔字段由日志和产物支撑，不能先填 true。

第八轮已跑的两条非OCR服务链有价值，但预算为合成输入、真实决算未冻结真值，不能替代上表正式四场景。当前运行环境已能使用 Docker，不再沿用2026-10-02的 daemon 不可达判断。

## 门槛与空白模板

| 门禁 | 发布要求 |
|---|---|
| 正式问题精确率 / 真实缺陷召回率 | ≥98% / ≥95%，仅独立盲测 |
| 高/重大问题漏报 | 0 |
| 精确定位 / 正式证据真实性 | ≥98% / 100% |
| 越界定位 | 0 |
| 确定性适用检查完成率 | ≥95%，分母预先冻结 |
| 状态与未完成原因覆盖 | 100% |
| 四格式语义及版本一致 / 同版重复运行一致 | 100% / 100% |
| 真实服务 | 四场景均完整通过 |

报告必须同时披露样本量和 TP/FP/FN；分层小样本的95% Wilson区间是描述统计，不能据点估计承诺普遍可靠。任何缺数据指标为 null/not_computable，不能填0或100%。跳过测试、合成样例的一致率和模型 raw_score 均不是上述业务指标。

模板位于 `docs/acceptance_templates/`：

- `dataset.template.json`：顶层清单，初始 documents 为空。
- `document-row.template.json`：逐文档分层、回放及四格式路径；补全后加入 documents。
- `golden.template.json`：原件身份、人工冻结及必查分母。
- `label.template.json`：单条人工标注；补全后加入 labels。
- `e2e.template.json`：四个场景名称，默认 pending、通过项为 false、身份/路径/SHA为 null。
- `freeze_record.template.json`：材料保管、独立复核、近重复/分歧处理及解封签认记录；由真实人员填写，不代表当前已完成冻结。
- `scan_attestations.template.json`：独立扫描原文/区域认证清单，与复核附件及SHA一起提交；不能由待测OCR生成。

模板故意不满足门禁；它们不是样本、真值或服务成功证据，不放入 corpus、不注册为冻结数据。按真实证据填写后才运行检查。详见 [已有数据格式说明](ZC07_真实验收数据格式.md)；可信OCR实施依赖见 [OCR任务](OCR_可信闭环实施任务_20261005.md)。

```bash
.venv/bin/python scripts/run_zc07_acceptance.py \
  --manifest /absolute/path/dataset.json \
  --e2e-evidence /absolute/path/e2e.json \
  --mode legacy \
  --output outputs/zc07_frozen_run/acceptance.json
```

CLI当前接受 `legacy`、`structured`。使用与实际回放模式一致的选项和对象键，不能传 `dual`；structured表示实际消费结构化解析结果的被测路径，并需满足评测器的覆盖要求，不能把dual/AI合并结果仅重命名成structured。清单不合格或任一门禁不足时退出2，保留未通过结果和原因。
