## 1. R1 [P1] 候选裁决没有校验原页金额覆盖 — 已修

**原问题。** 上一轮只删掉了“按数值相同判重复”，但结构分 `非空格/总格` 仍会奖励
删掉整列的候选：完整候选有一格真实空白 → 26/27 = 0.96296；缺列候选每格都填满
→ 24/24 = 1.0，于是选中漏列的候选。

**修法。** 裁决改为**覆盖优先**：

- `PDFParser._token_claims()` 抽出“原页字符 token → 认领格位置”的统一口径；
- `_covered_amount_tokens()` 返回候选认领到的**不同 token 数**；
- `source_reconstruction` 的平局分支先比覆盖数，覆盖相同或任一方无 token 证据时
  才退回结构分（不能把“没有证据”当成“覆盖为零”）。

位置：`src/services/pdf_parser.py`（`_token_claims` / `_covered_amount_tokens` /
`_structure_priority`）、`src/services/source_reconstruction.py`。

**证据。**

| 反例 | 修复前 | 修复后 |
|---|---|---|
| 复核方 `extended_probes.py`：完整候选 15 token、缺列 14 token | 选中 `lost` | 选中 `full` |
| 全覆盖差分：12 份真实材料（2022–2025），旧裁决 vs 新裁决 | — | **0 份差异** |

回归测试：`tests/test_native_geometry_candidate.py`
（`test_coverage_outranks_structure_when_one_source_column_has_a_real_blank`、
`test_coverage_is_ignored_without_token_evidence`）。

## 2. R2 [P2] 只提交 table_identity 时校正结果不进入回执 — 已修

**原问题。** 主链路只统计 `cell_value` / `table_rows` / `column_mapping` 三类校正，
只提交表种确认时 `fact_overlay` 恒为 `not_requested`，失败原因无处可见。

**修法。**

- `apply_table_cell_overlays()` 给每条回执与目标打 `field` 标记，并输出
  `report["by_field"]`（`cell_value` / `table_rows` / `table_identity` 各自 applied/unresolved）；
- `api/main.py` 新增 `has_table_identity_changes`，独立输出
  `fact_overlay["table_identity_overlay"]`，失败原因以“表种确认未生效：…”并入
  `unresolved`，状态置 `failed`/`partial`，成功置 `applied`。

**证据（真实离线完整管线，鲁迅纪念馆 2023，目标 `UNKNOWN_P15_T0`）。**

| 提交表种 | 修复前 | 修复后 |
|---|---|---|
| `NOT_A_REGISTERED_TABLE` | `{"status":"not_requested"}` | `{"status":"failed","table_identity_overlay":{"applied":0,"unresolved":[{"reason":"提交的表种未登记"}]}}`，复核原因新增 `correction_overlay_incomplete` |
| `FIN_02_income`（有效） | `not_requested` | `{"status":"applied","table_identity_overlay":{"applied":1,"unresolved":[]}}` |

证据文件：`outputs/intake_remediation_20261024/fix_verification_round2_20261026/identity_pipeline_result.json`
与 `identity_pipeline_valid.json`。

回归测试：`tests/remediation/test_manual_cell_fill.py::test_identity_only_overlay_reports_under_its_own_field`。

## 3. R3 [P2] 整行补录被拒后表种已被改动 — 已修

**原问题。** `_apply_table_rows` 先确认表种（就地改 table 与逻辑实例），再校验金额列；
校验失败直接 return，已改的表种没有撤销，且 `applied=0` 使审计/指纹不更新。

**修法。** 快照在**确认之前**取；金额列校验失败时调用 `_restore_table_code()`
把 table 与全部相关逻辑实例恢复原值。

**证据（真实 `UNKNOWN_P1_T0`，金额列填“非数字”）。**

| 观测项 | 修复前 | 修复后 |
|---|---|---|
| `applied` | 0 | 0 |
| table 表种 | FIN_02_income（被改） | **UNKNOWN_P1_T0** |
| 逻辑实例表种 | FIN_02_income（被改） | **UNKNOWN_P1_T0** |
| `parse_run_uid` | 未变 | 未变 |
| `processing_manifest` | 空 | 空 |

回归测试：`tests/remediation/test_manual_cell_fill.py::test_rejected_rows_restore_table_code_and_instance`。
