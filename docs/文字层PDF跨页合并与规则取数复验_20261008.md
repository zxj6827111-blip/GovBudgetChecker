# 文字层 PDF 跨页合并与规则取数复验

日期：2026-10-08。范围：桌面“决算测试上海市”20 份原始 PDF 的导入、表格重建、规则取数与真实服务复验。

## 结论

这 20 份原件的 678 页全部具有文字层。本轮复现的问题来自表格边界、跨页列布局及规则取数，已按原生文字提取路径修复。在本批材料范围内，PDF 导入、核心表重建、跨页合并、入库读回及规则执行主链通过自检。

识别到 180 个核心表实例，其中 81 个跨页表已重建为逻辑表。13,443 个金额事实逐项核对了原始单元格、原始页码、坐标、原文金额、单位换算与文件哈希，来源核对错误为 0。所有原 PDF 的哈希保持不变。

另反向核对了 100 张功能分类及基金表所在原页的可见完整科目编码，均能在重建后的对应逻辑表中找到，未发现这类编码行遗漏。该项核对记录为 `outputs/native_pdf_core_20261007/native_row_presence_check.json`。

这项结论是本批原件的功能复验结果。报告中的检查完成率用于说明可执行范围，不能作为问题判断准确率，也不替代整个产品的独立验收。

## 已修复内容

1. 续页没有表题、首页“类／款／项”拆成多列而续页使用完整科目编码时，按实际金额列边界对齐；合并后的金额仍保留原始行、原始列、页码和坐标。
2. 财政拨款总表的稀疏续页、“人员经费合计／公用经费合计”单独占页，以及上下边框不闭合的原生数据行，纳入表格重建。表头编号保持为表头，不形成金额事实。
3. 同一张表按线框和文字间距提取的重复结果去重；说明段落不再形成第二个核心表实例。明确“无此项／本表无数据”的基金空表保留空白，不制造零金额。
4. 缓存存储增加原始列号，读回时保留空列和表头。数据库迁移编号为 `2026-10-07_0029_parse_original_columns`，解析器指纹更新为 `pdfplumber-cells-v11-native-continuation-columns`。
5. 规则读取当前事实所绑定的合并表。收入表使用收入列口径；合计按互不重复的上级科目求和，避免遗漏只披露到类／款的科目；财政拨款“总计”与“本年支出合计”分别取数。
6. 三公说明按同一业务分项、同一决算阶段比较，输出关联事实和证据。全角千分位、中文间距、页尾页码及金额首个千分位组中的空格已补充处理；不同金额列不拼接成一个金额。
